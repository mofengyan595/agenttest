## 4B 新样本与机制

[新任务](../examples/stage4b-tasks.json) B01–B04 独立于 T01–T18；两条可支持的自然语言任务、两条删除/伪造权限的拒绝任务。由开发者构造，**未声称逐条获得人工评测标注批准**；业务预期复用已批准策略。既有 18 条、两轮模型数据均不修改。

| 机制 | 配对的可信预期 | 规划评测范围 |
| --- | --- | --- |
| 响应 name 不一致 | 查询 name 等于创建输入 | B01 自然语言 |
| 响应 ID 不一致 | 查询 ID 等于创建动态 ID | B01 自然语言 |
| 创建错误状态码 | 创建必须为 201 | B01 自然语言 |
| 归属检查缺失 | 他人查询必须为 403 | B02，仅 mini target |
| 异步终态错误 | FAILED 不得冒充 SUCCEEDED | 人工固定异步执行基线 |
| 结果条数错误 | CSV 两行对应两条结果 | 人工固定异步执行基线 |

每种缺陷有全新正常目标作为对照；故障开关只由操作员配置，不发送给模型。每个自然语言任务只生成一次计划，在内存中复用于正常/故障目标，不因发现失败重新规划。异步路径没有冒充模型规划能力。

- manual：读取标注的人工计划，是策略及执行器对照，不代表自然语言理解。
- fake：固定 B01 样本，是链路基线；跨意图失败是预期边界。
- real：学校模型只看到需求和经过筛选的契约/策略目录，没有 Golden Labels、故障设置或凭据。显式开启、串行最多 4 次，Token 总预算 90,000（每次最大保留 22,048），不自动重试。
- 两条支持任务分别统计计划有效、策略选择正确、独立意图满足和正常链路成功；拒绝任务单列，不能用拒绝任务充当有效计划分母。
- 缺陷检出要求 ASSERTION_FAILED 且失败断言对应注入机制；正常对照失败才是误报，故障执行 PASS 才是漏报。基础设施/工具错误列为 inconclusive，不伪装缺陷或成功。
- 未执行的故障单列；预算导致未执行的支持任务仍留在规划指标分母，不提高指标。
