# 项目接入与网页使用 Goal（2026-10-24）

目标：完成项目 → 测试助手 → 测试记录的本地产品闭环。仅授权专用合成目标写入，
不使用付费模型，不修改 CourseInsight，不建立 branch/worktree，不 commit/push。
复用既有规划、授权、执行、报告与固定回归能力，不新增架构或历史质量对照。

历史全部归档保持冻结：候选完整任务9/18、足额9/15、项目3/6、批准负例85/105；
三项质量目标未达成，独立人审与节时均未验证。

## 核查结论

- 首页 Workbench 的文本仅保存草稿，不能提交；独立 tasks 页面才连接任务服务。
- ContractImport 调用 summary，仅解析，不保存文档或登记项目。
- TaskService 从操作员登记文件装载项目；SQLite 已持久化任务，支持会话、去重、取消、配置一致性。
- 当前代码已支持三层需求、完整分母、可信规则派生、证据及通过场景导出。
- 接入需要业务映射、目标许可与服务端身份，不能从接口文档推导授权。

## 实施检查点

1. 固定目录持久化网页接入元数据，明确草稿、待补充和可提交状态；绑定服务端授权配置。
2. 三处导航、可理解的接入表单、真实提交入口、运行来源和结果摘要。
3. 模拟模型及两个合成业务域的完整浏览器操作、固定回归、桌面/手机截图和异常反馈验证。
4. 更新进度、能力边界、单一本地启动说明；据实分别判断工程/模型质量/用户体验。

## 支持边界

网页可以新建并保存任意有效 OpenAPI 文档草稿。可执行接入必须选择服务端已经授权的配置，
上传文档的解析结构必须与该配置一致，并显式确认当前版本的业务预期。
配置来自已有引擎支持的操作、角色及规则，不要求普通用户编写 JSON/DSL/TaskContract。
新业务映射仍由操作员在服务端提供；网页不能自行批准地址、添加账号密钥或从文档采信业务预期。
这是实际保存的新项目身份与版本，不修改或覆盖授权源文件。
