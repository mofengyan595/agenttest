## 修复与门禁

- 固定输入分支从生成结构中省略动态来源开关。旧格式的 `false` 保持可解码，错误类型和无来源时的 `true` 仍拒绝。动态输入仍需明确来源选择。
- 相邻的明确字段或状态检查可关联上一分项唯一的同身份读取。要求已选操作和已审查的匹配断言。多选状态、身份不符或无相符断言继续报缺口。计划阶段仍核对具体执行步骤和见证。
- 两个单步骤只读提案只有同一身份、无动态绑定且具有现成的批准前置关系时，才在构造阶段进入同一场景。构造器保留两个节点及其策略，随后统一检查依赖、预算和执行授权。缺少节点、写入、跨身份或多解关系没有自动补齐路径。
- 等价合并只作用于全只读计划中同种类的单步骤 GET 或 HEAD，要求操作、身份、策略和全部输入一致。含前后状态、明确重复、独立的原文动作、动态输入、前置或轮询的用例保留。混合读写计划保留写入两侧的读取，写入重复校验继续独立执行。合并后重新核对原文、状态及响应断言，任务记录保留合并数量。
- 任务计划记录直接保存脱敏的细分诊断及字段位置。已有模型记录仍能区分截断、JSON 错误、Pydantic 拒绝与业务校验。历史证据中五个位置均属后者。

## 离线验证

新夹具在旧实现上有 6 项按预期失败、5 项边界用例通过。候选的相关 pytest 共 237 项通过，包括默认分组预算、状态和内容见证、错误来源、写入重复及跨身份检查。Ruff、`git diff --check` 和真实本机 HTTP 工作流冒烟通过。冒烟使用本地确定性规划，8 个步骤和 9 次请求，不计入真实模型验收。

冻结前复现了混合读写计划会合并两个相同读取的反例。加入只读边界后，同一回归保留两个读取和中间的写入提案。候选提交门禁共 109 项通过。

## 下一轮真实验收

在用量门禁恢复后，以 `057aafa` 对比本轮冻结候选，使用同一模型、预算、配置和目标。新题覆盖已知合法的固定资源、状态及字段检查、跨接口只读前置、真正冗余和有意重复的读取。验收侧预先冻结原文和预期，保留所有位置、环境错误、实际请求、用量和耗时。比较同一批的错误拒绝数、静默漏项、越权请求及每位置调用与延迟。历史 8/36 仅作背景，正式结论由新的配对差异决定。

基线 G12 第 2 轮设计调用返回 HTTP 500，仍保留为 `UNKNOWN`。本轮根据操作者答复单独登记了该调用的例外，已核对原账本记录保持一致。新题配对使用独立工作台、现有授权的本机 Gitea 和 Petclinic，采用每个位置只提交一次的首次计分口径。
