## 完成判定规范

1. **Execution**。已派发 HTTP 可从请求账本与尝试核对。通过 `flags.evidence_produced` 和报告确认是否有实际断言。规划、预检或工具返回不足以证明业务测试执行。
2. **Coverage**。`scope_ledger.coverage.requested` 衡量原文要求，`selected` 衡量选中义务，`approved` 给出项目全景。完整发布检查应覆盖批准项目范围。窄请求需要有原文及批准合同或实例依赖佐证。相同资源生命周期可推导创建、删除和批准的缺失观察，无关兄弟动作和可选状态探针不构成意图。
3. **Test Verdict**。继承报告的 PASS、ASSERTION_FAILED、NEEDS_REVIEW 等。断言失败可提供可靠覆盖和业务异常证据，故障原因仍需额外证据。覆盖 1/1 不等于断言通过。
4. **Investigation**。观察到批准断言偏离即确认表现。成功调用但未见偏离，只能说明本次未复现。超时或缺少断言时保留原因未知。原文要求查因时需按证据说明是否能定位。
5. **Cleanup**。由现有 `write_effects` 凭据判定已证明清理、未证明或失败。204 本身不足以证明已删除。集合 POST 收到 422 且看不到已批准的副作用确认时，保留 `CREATION_UNPROVEN`。独立靶场终态为零不能替代运行期凭据。
6. **Strict Completion**。要求真实断言、必要义务的覆盖、影响本轮的待确认事项已解决、资源安全。已确认的断言失败不会重置执行和覆盖证据。仍有任何必要条件未满足时维持 `complete=false`。`APPROVED_SCOPE_COVERAGE` 继续展示差异且为 EXEMPT。排除理由不会把确实要求而缺失的检查变成完成。

| 行为 | 应满足的规范 |
| --- | --- |
| 同资源新增、查、修改、删除均有证据，批准的删除后回读通过且清理证实 | 可严格完成。未测健康探针或另一种未要求的同资源修改方式不阻塞 |
| 同一任务漏掉明确点名的读取或替换 | 仍未完成，选择、分组或预算理由不构成覆盖 |
| 仅复现一个确定的只读探针，看到批准断言从 200 偏离到 503，证据完整 | 调查复现完成，断言失败，内部原因未知 |
| 删除返回 204 且同资源仍返回 200 | 删除缺失检查已覆盖，断言失败，清理失败，严格未完成 |
| 对明确选定的批准负向检查未发请求，或 422 副作用未证明 | 严格未完成。请求覆盖和资源凭据分别报告 |
| 原文未指明测试对象 | 合理澄清，保持零业务请求，严格未完成 |
