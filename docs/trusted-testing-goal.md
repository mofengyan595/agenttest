一、最终目标

用户完成项目首次接入后，只需提出测试需求，Agent 就能够在已授权范围内：

- 为单接口生成并执行正常、边界和已批准的非法输入测试。
- 为多个接口组织认证、动态资源、角色与状态依赖。
- 为项目生成完整、预算可解释的分组测试计划。
- 面对不同表达和第三个项目，继续复用相同核心代码。
- 输出实际覆盖、断言结果、证据和未完成原因。

本轮以提高实际测试完成质量为主线，优先解决当前失败来源。

受支持的新需求仍不要求用户手写完整步骤、资源偏序或逐题 TaskContract；未知业务预期保持澄清或待审。

三、阶段1：让批准的负例真正可执行

先查清当前非法输入在候选生成、计划校验、请求校验和断言阶段分别如何被处理，明确根因。

在现有 DSL、Policy、Executor 和 Verifier 上增加受控负例能力：

1. 用项目级批准规则说明目标接口、变异字段、变异类型、取值范围和可信错误响应预期。
2. 模型只能引用批准的测试能力；具体非法输入由确定性代码构造。
3. 支持当前 Schema 子集内的必填缺失、类型错误、枚举外值和边界越界。
4. 正常请求继续执行原有完整校验；负例仅允许命中批准的预期违例。
5. 其他字段、目标地址、操作、角色、凭据、资源来源和请求大小仍受原门禁限制。
6. 无批准错误预期的候选继续待审，不能猜测状态码或错误正文。

禁止添加通用 skip_validation 开关，禁止为了发送负例而全局放宽请求校验。

OpenAPI 字段约束可以支持生成输入变异，但不能自动证明某个具体业务错误响应正确。

报告明确区分：

- 正常输入验证通过。
- 已批准的非法输入被目标按预期拒绝。
- 目标响应违反可信断言。
- 测试基础设施或工具失败。
- 预期未知、未执行或待审。

在专用合成目标中验证正常拒绝、错误接受非法输入、错误响应不符合策略，以及未授权变异被阻断。

复用原固定模板，将通过的负例导出为可在模型禁用条件下执行的 pytest 回归。

四、阶段2：提高项目级规划完整性

审查现有 STEP_COUNT、STEP_SET、额外目标、缺失依赖、状态策略错误和预算排除等真实失败，依据保存的计划与诊断分析，不猜测模型内部推理。

在原引擎内改进：

- 根据批准关系确定项目范围、分组、必要依赖和覆盖分母。
- 每次规划只提供当前组所需的公开接口、策略、角色与资源关系，减少无关目录干扰。
- 模型负责计划提案；执行前仍检查遗漏、额外操作、参数来源、角色、状态和顺序。
- 不静默补步骤、重排模型计划或替换策略。
- 不向模型提供逐题参考计划、隐藏评分标准或标准答案。
- 不将模型照抄确定性计划包装成自主规划收益；分别记录模型与规则贡献。

项目与子用例共享固定总预算，入口语义调用、规划、反馈、调查和实际请求全部计入。

预算预览至少展示：

- 必需业务请求。
- 可选调查额度。
- 可以执行的组。
- 无法执行的组及原因。
- 完整项目是否在当前预算内可完成。

分别验证“预算足够完成”和“预算不足安全退出”。新验证预算在运行前冻结；不能修改旧预算后重算旧成绩。

项目级结果必须同时提供接口和场景的候选、计划、执行、断言与未执行分母，不能以部分通过冒充完整项目完成。
