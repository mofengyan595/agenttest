## 真实流程与样本边界

- 基线 `4b5c24f`，候选 `78f5158`。两个独立工作台使用同一 `ecnu-max` 配置、相同项目文档和预算。每任务最多 12 次目标 HTTP，沿用模型 9 次、500,000 Token 的任务预算和每次 60,000 输入、8,192 输出、70,000 总量限制。模型用量缺失时按原机制停止。
- Gitea v1.26.3 为首次通过此项目接入路径验收的代码托管服务。核对上游 Windows 包 SHA-256，新建仅监听回环地址的 SQLite 实例，以隔离账号准备公开和私有仓库，再使用只读凭据执行。上游导出为 Swagger 2，本轮按选中 GET 的上游路径、操作 ID、参数和状态生成 OpenAPI 3 子集。该转换在验收侧完成。[上游发布](https://github.com/go-gitea/gitea/releases/tag/v1.26.3)
- Petclinic REST 使用固定上游提交 `afc8fc1d3b8ec8de69414482b3bd70a1da78cb95` 的已核对 JAR，使用独立内存 H2 和公开种子数据。只从运行时契约选取兽医、专科、宠物归属和分页读取。候选运行所用文档与基线相同。
- Gitea 首次接入用网页上传、读取建议、预览、确认、保存和提交测试。浏览器脚本实测 10 个操作，保存用时 0.989 秒，首次测试和取证结束共 13.190 秒。首次目标为版本接口，HTTP 200，任务完整。该耗时是自动化墙钟时间，未做人工用时比较。之前有一次脚本走到旧页面入口，未提交任务、未调用模型，原失败收据保留。
- 24 条新需求、27 项目标预检，按两版各两轮计划共 96 位置。每一对通过普通网页各提交一次，等待该对结束后进入下一题。第二轮交换排队顺序和领域起始顺序。参考答案只在评测侧，独立于运行端和模型。同一开发者准备和审阅，未进行独立人工盲审。

基线 G05 第二轮项目登记返回本地会话校验 403，未提交测试，仍保留在 36 个执行位置中。基线 G12 第二轮的设计模型返回 `MODEL_SERVICE_ERROR`，服务没有提供用量。已知的选择调用 5,822 Token 继续计入，设计调用的用量保留为 UNKNOWN。该对是最后一对，比较在用量门禁停止，没有重复提交。Gitea 首次接入的模型用量单独保存在收据，未计入 A/B。

核对归档的 565 个成员摘要，并从解封文件重新计算 96 个位置。验收结束后，两个工作台和两个隔离目标进程均已退出，对应的四个端口没有监听。

首次完整执行按实际操作、身份、输入、已批准状态及内容断言、同一场景内的顺序和多余请求判定。没有执行证据的批次仍保留原分母。逐项漏项口径基于冻结要求和可审计的任务记录，规划拒绝与环境失败保留不同原因。重复只读场景与模型输出结构错误仍存在，候选的错误拒绝率未下降。

## 冻结后补修

Petclinic 的混合位置暴露两种范围错误。模型把未批准的输入仅放入待确认问题时，冻结候选仍可能发起默认值读取。模型只在问题中注明未批准响应断言涉及的接口时，候选可能执行该接口以及独立检查。两处均以独立离线夹具复现为两个 GET，修复后仅发送独立健康 GET。同接口有另行明确要求的正常场景时继续保留。补修不改变冻结成绩。真实模型用量门禁触发后，补修的验证范围为离线。

## 可核对范围

明确字段、显式 JSONPath、已确认状态与可验证资源关系能对账。复杂中文、无选择器表达、混合语义归属和同一操作跨身份的部分授权仍有不确定范围。目标均为隔离只读实例，跨写入依赖、清理失败和未知写入不重放沿用离线验证。完整实验和待确认位置按冻结证据归档。
