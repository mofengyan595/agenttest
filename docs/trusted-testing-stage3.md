# 表达入口与第三项目复用记录

## 核心机制冻结前的表达改动

原受控语法继续可用，没有为新验收题添加逐题映射。新增统一的全半角/Unicode 排版、接口标识
大小写、方法路径空白及反引号规范化。原文摘要保留，测试字面量先从原文提取，不改变引号内的数据。
规范化后的标识发生多义时继续拒绝，而非任选一个目标。这是有限的表达适应，不等同任意自然语言理解。

项目可显式启用 `semantic_goal_drafts`。无法解释的原文可由现有模型传输提出 GoalSpecDraft，
仅含范围、注册目标 ID 及原文字符跨度、未解决跨度；不含步骤、地址、角色授权、资源偏序或可信断言。
检查注册引用、越界、重叠及未覆盖原文；未解释要求不静默删除。草案结构通过仍保留
`semantic_verified=false / NEEDS_REVIEW`，不能从后续计划反推验收目标，也不能自行执行陌生业务语义。
用户澄清只需明确目标，无需填写步骤或 TaskContract。草案本身不作为新权限的批准。

CLI 与任务服务的草案调用在同一任务/套件运行中使用 SuiteLedger；计入模型、Token 和既有会话额度。
未知用量、超时或额度耗尽后不重试；任务服务澄清继续使用已消耗的账本。原文限内存，SQLite 只保存
摘要、注册目标、跨度、用量及待审原因。秘密值在发模型前检查。默认关闭，现有项目身份与原封印兼容。

使用 OpenAI Docs 核对了结构化输出与语义的区别，复用原 JSON/兼容供应商传输，没有增加 SDK 或模型。
官方文档说明结构化输出仍可能有内容错误，并区分 JSON Schema 的结构约束；
因此不能将结构通过当作自然语言语义证明。[官方结构化输出说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。
本阶段新草案适配器目前为 Fake/Mock 工程验证，尚未宣称真实供应商语义能力。
