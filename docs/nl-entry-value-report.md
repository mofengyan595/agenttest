# 自然语言入口：实际价值与边界

本轮将“每题手写完整TaskContract”改为一次接入项目配置、随后输入支持范围内的原文。系统从批准
关系派生本地门禁，模型负责生成计划及选择有界调查，执行和结论采信继续由可信引擎负责。
这是工程使用路径的改善；是否更省人工时间或具备通用规划稳定性，没有独立使用者证据。

所有新结果为DEVELOPMENT_ONLY / UNREVIEWED，独立人审0。旧完整产品29/36与31/36、正常17/18与
18/18（差异含超时）、主动正确弃权3/6与0/6，以及NU01首次真实/无模型回归均保留，不能跨协议算增益。

## 协议与输入隔离

新12原文为6单接口、4流程、2项目，课程/工单两域；逐题评分标签只在评分器使用。运行输入只有原文
和项目级配置；目标词汇目录不包含逐题原文、步骤或答案。评分独立检查应有策略/接口集合、计划数量、
角色、顺序、Schema变体、实际请求及指定故障断言，不只相信产品自己的task_satisfied。

源码、任务、公开输入、模型、预算与评分在运行前冻结。每run最多4模型/2只读，每位置最多8模型/
10总请求/100000 Token，零隐式重试；未知用量/模型传输或基础设施错误停止后续付费，剩余位置保留分母。
模型原文与内部推理未保存，不能猜测其思考过程；可核对实际计划摘要、拒绝分支、决策提案和请求证据。

## 模型贡献与可信机制

目标识别、授权、依赖与意图门禁、预算和症状规则均是确定性机制。模型负责实际DSL计划及调查提案，
不能把这些门禁或规则输出计入模型成功。

原排期8次故障运行实际发出10次只读调查，5次具有规则支持症状；模型严格匹配结论和完整证据引用的
finish只有3次。另有2次虽同为越权结论，却引用了与规则支持链不同的调查，最终没有采信。
3次在规则证据不足时仍提出确定性缺陷结论，最终保持EVIDENCE_INSUFFICIENT；模型主动明确弃权0。
因此不能宣称模型诊断稳定或能可靠识别证据不足。模型原文和内部推理没有保存，不猜测失败原因。

## 明确的失败与未覆盖部分

1. getCourse在正常回读与跨用户拒绝之间有多义；缺少预期保持澄清。未批准删除工单不产生HTTP。
2. 单接口正常/枚举/合法边界可执行；必填缺失、类型错误等没有批准错误响应语义时列待审，不猜状态码。
3. 工单项目六组需11次请求，原授权10次，最多允许5组进入规划/执行；实际执行还受模型门禁限制。
   最后列表组不是漏报后被删除的分母。
4. 原生Function Calling只有Mock；当前供应商真实排期采用JSON。任务上下文不是长期记忆，重启不恢复执行。
5. 所有业务为专用ASGI合成目标；不等于真实Java/PocketBase/生产系统验证。Docker守护进程当前不可用，
   本轮没有添加或声称验证Docker交付；默认无Docker路径不受影响。

本轮工程入口已打通，但原完整任务15/36与诊断弃权0说明正向质量目标尚未全面达到。阶段结束后冻结
范围，不继续用已用题调参或无限重试；正式独立人审仍需真实参与者和未用需求。
