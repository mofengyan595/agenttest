# CourseInsight 网页测试启动与使用

本轮沿用原 Demo 数据库和队列。已有业务数据保留，仅本轮新建且有归属证据的资源可写。
本轮当前26操作均有实际请求及通过记录；首次、复验和固定回归分别保存，详见
[交付、计数与限制](courseinsight-colleague-delivery.md)。旧的“23 个可解析接口”仍属历史。

## 启动 AgentTest

在 `D:\Desktop\project\agenttest` 打开 PowerShell：

已有服务运行时直接打开页面，不重复启动。需要启动时：

```powershell
Set-Location -LiteralPath 'D:\Desktop\project\agenttest'
.\scripts\start_web.ps1 -Port 18520 `
  -Data runs/courseinsight-colleague-20261103/workspace `
  -ModelEnv runs/courseinsight-colleague-20261103/runtime/model.env
```

打开 `http://127.0.0.1:18520`。此命令使用已配置真实规划模型；不加 `-Demo`。
`model.env` 是本机私有资料，不提交、不下载到浏览器、不放进需求或报告。
账号、密码、Token 的值只在服务端配置，页面只填 `AGENTTEST_TARGET_…` 变量名。
若修改了代码，先在 `web` 运行 `npm run build`，确认没有运行中的任务后再重启服务。
不要因网页暂时无响应而重新发送创建、上传、重新入队等请求。

## 原 CourseInsight 实例

已有容器为 `courseinsight-demo-mysql`、`courseinsight-demo-redis`、
`courseinsight-demo-rocketmq-nameserver`、`courseinsight-demo-rocketmq-broker`、
`courseinsight-demo-ai-service`。使用现有容器和存储，不新建、不清空、不整体回收；
另一个 `courseinsight-mysql` 不属于本轮。AI 原入口为 `127.0.0.1:8002`。

后端本轮从 `runs/courseinsight-colleague-20261103/runtime/server` 的源码副本运行，
配置读取同级上层私有 `demo.env`；没有修改 CourseInsight 仓库。Java 17 已在本机安装。
当原端口 8080 没有服务且无进行中的任务时，可在该源码副本目录运行：

```powershell
Set-Location -LiteralPath 'D:\Desktop\project\agenttest\runs\courseinsight-colleague-20261103\runtime\server'
$env:JAVA_HOME = 'D:\Java\jdk-17'
.\mvnw.cmd -o spring-boot:run '-Dspring-boot.run.profiles=demo'
```

这是正常真实 AI 路由。定向失败夹具仅用于本轮已登记合成文本的恢复验证；它的结果必须
明确标为受控失败，成功恢复仍需原真实 AI。本轮已恢复正常路由并停止夹具；不能把夹具当业务服务。
数据库在原实例有历史内容，页面“隔离”勾选不代表创建了独立空数据库。

## 用一句话发起测试

本机保留两个项目。“CourseInsight 本轮真实接入”可检查健康、登录与课程列表；
“CourseInsight 完整业务接入（本轮资源）”当前保留空课程创建、更新、读取、删除与登录。
后者可直接复制已验收原文：

> 创建编码“ATF03_20261103_6A2D”的空课程，将名称改为“验收空课更新_6A2D”，读取并核对新名称、编码和教师显示名，最后删除同一课程。

当前选择范围和历史26接口覆盖分别显示；扩大范围需先核对相关配置。

“已保存测试”中空课程写回归、健康和课程列表可直接再次运行。旧配置下的size0、CSV和
结果等资产保留原记录，配置变化后暂停独立运行；不能绕过版本检查。

1. 在“项目”导入当前 OpenAPI 文档，或继续已保存的项目。更新建议会保留已有配置。
2. 核对接口、身份、输入来源和检查依据。凭据使用变量；资源可来自已确认的本轮收据，
   或选择前置接口的响应字段。不要猜 ID，也不要从历史列表拿别人的资源做写测试。
   文档中明确可选的普通字段可以选择“暂不发送”；重新添加时按文档建议核对。
   必填字段和受控凭据校验不因此放宽。
   若检查依赖写入后的状态（例如删除后查空），在该读取接口的“执行前置条件”选择
   必须先完成的操作。系统安排依赖，错误顺序在请求前停止。固定合法输入也可单独勾选
   “允许异常检查”，仅授权文档支持的单字段拒绝场景，不改变合法基线。
3. 上传接口选择专用合成 CSV；异步查询开启有限等待，并写明预期终态及结果内容检查。
   提交成功、HTTP 200 和“仍在处理中”都不能代替成功完成。
4. 进入“当前测试”，输入要验证的行为，点击“开始一轮测试”。例如“检查健康状态与
   课程列表内容，说明还有哪些没有测到”。系统安排登录和已批准的资源依赖。
5. 查看实际请求的接口、完整执行的场景、失败字段和未执行原因。配置就绪、文档可解析、
   实际请求和检查通过是四种不同事实；任务结束不等于整个需求通过。
6. 对可保存的稳定场景点击“保存测试”，在“已保存测试”再次运行固定回归。
   固定回归禁用模型，只证明固定步骤仍符合原检查，不代表新的一句话理解成功。

配置版本变化会使旧资产暂停独立运行，避免以旧授权执行新配置。原报告保留。
上传、轮询和受保护输入等场景仍可能超出固定回归包支持范围，页面应显示具体原因；
不要为保存资产删掉断言、移除隐私检查或改写失败记录。

## 中止、未知用量与清理

取消不会回滚已经发送的请求。写入结果未知时先查本轮收据和服务端状态，不自动重放。
模型没有返回用量时保留 UNKNOWN；本 Goal 用户已明确允许后续继续，逐调用授权例外
与原 UNKNOWN 分开记录。其他操作员的默认停止规则不改变。

空课程通过正常删除接口清理。非空课程限制不得绕过；账号、批次等没有删除接口的资源
在复用原库的条件下保留待清理，记录所属运行，不删除原存储或用户旧数据。

原始任务、逐接口清单、收据、配置快照、代码版本和用量记录位于
`runs/courseinsight-colleague-20261103/`，其中 `runtime` 为私有运行资料。
