# 开发检查

在项目根目录，使用项目虚拟环境运行：

```powershell
.\.venv\Scripts\python.exe scripts/check_dev.py --area product --jobs 3
```

按本次改动选择范围，使用 `--list` 可以先查看全部文件：

| 范围 | 覆盖 |
| --- | --- |
| `focus` | 自然需求、输入、来源和字符串长度 |
| `intake` | 通用接入、接口清单、结构与工作区身份 |
| `execution` | 产品任务、取消、异常检查与范围 |
| `contracts` | 契约解析与请求校验 |
| `tasks` | 原任务服务、持久化、项目接入和用量 |
| `product` | 所有产品测试模块、接入、清单、用量和工作区；自动包含新增产品测试文件 |

小范围使用默认串行，避免多个进程的启动开销；较大范围可使用三批并行：

```powershell
.\.venv\Scripts\python.exe scripts/check_dev.py --area focus
.\.venv\Scripts\python.exe scripts/check_dev.py --area product --jobs 3
```

先执行一次 Ruff，再把选中文件分成互不重叠的批次，每份文件只交给一个 pytest 进程。
历史报告仅用于估计分组耗时，不复用历史通过结果。各批使用独立临时目录，保存日志与
JUnit 报告；异常退出、报告缺失/损坏或900秒超时均不能报通过。
`runs/dev-checks/<本次编号>/result.json` 保存范围、分组、结果、实际墙钟与各批耗时之和，
两种时间分开报告。该入口不调用模型或业务网络，也不改变产品真实任务的执行顺序。

这是开发反馈入口，不是完整发布验收。全量 `python -m pytest -q` 的默认收集范围保持不变。
修改公共执行或安全逻辑时，应额外运行相应回归；前端变更按范围运行前端测试、类型检查和构建。
稳定版本集中做全量离线和完整浏览器检查，避免在每次小改后重跑整套历史评测。

固定回归继续禁用模型；新的测试设计仍使用真实配置模型。缓存只复用按原始文档字节验证后的
解析结果，不复用测试结果、身份、执行权限或请求，且每次返回独立数据副本。

网页中重复验证同一只读场景，使用“已保存测试→再次运行”；只验证本次关注的流程时填写
具体重点，避免每次都安排全项目。新的模型能力验收与完整发布验收仍独立进行，不能用固定
复测结果代替。本轮v16历史三轮验收和归档保持不变。

## 完整离线与真实模型验收

完整离线入口使用所有默认收集的测试，不接受局部文件或筛选环境变量：

```powershell
.\.venv\Scripts\python.exe scripts/check_full.py --jobs 4
```

可选择1至6个进程。先收集全部ID，再按历史耗时分成不重叠文件批次；每批独立临时目录，
保留源码快照/ZIP、首次事件和JUnit。最终逐个核对收集与实际终态ID，遗漏、重复、源码变化、
失败、损坏报告或非零进程退出均不能报成功。不会以跳过慢项来提速。
结果在 runs/full-checks 的本次独立目录；实际墙钟和各批测试耗时之和分别报告。

真实模型验收保留默认串行。仅新的验收或性能调度文档明确声明
`execution_mode: PARALLEL_PROJECTS_ISOLATED` 时，才可使用
`scripts/run_colleague_acceptance.py --manifest <本次文档> --project-jobs 3`。
还须提供该Goal已有的未知用量继续授权；其他操作者继续遵守默认用量停止。
`--plan` 只做资料检查并显示排程，0模型调用，不占用首次排期。
不同项目使用各自数据库、身份、目标端口和证据目录；项目内轮次及有依赖的请求仍按顺序。
首次失败不重试，所有位置及未执行项保留；旧v1-v16文档没有并行声明，不能据此改排或重跑。

复用已有任务测调度速度时，必须另建 speedcheck 记录并标为性能复跑，不能算作新的质量验收。
调度优化不修改模型提示、参数、断言或已保存的历史成绩。

本次完整离线和真实模型的实际等待时间、工作量及限制见[实测记录](validation-performance.md)。
