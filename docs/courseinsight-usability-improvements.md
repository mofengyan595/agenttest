当前导出的文档包含26个操作。用户首轮主动选择健康、登录和课程列表三个接口，实际执行

因此，它证明这条登录与读取链路跑通，不证明26个接口全覆盖或响应业务内容正确。
原任务62b1d6b9ecb0403fa34a7a2adcb486fa和原报告b3b4355385124c12ac38c784c992c600保留。

本轮参数解析可识别范围从20/26扩大至23/26：用户查询、角色修改和注册中的常见pattern
规则现在可以解析、生成有效示例，并进入模型方案约束与确定性请求校验。此计数仅指文档
参数兼容，不是可立即执行数、已测数或成功数。

- 用户查询仍需确认身份与范围；角色修改还需专用测试用户和写入授权，本轮没有执行。
- 注册参数可以解析，但非登录敏感输入尚无专用凭据注入路径，仍不开放执行。前端不提供
  普通密码输入，服务端拒绝把明文密码保存进项目草稿；手工配置也不能绕过该边界。
  此检查覆盖对象和数组内的敏感字段，不为其自动生成或保存普通输入值。
- 文件上传和两个长异步操作仍未接入通用流程；不能把提交成功当成分析完成。
- 其他课程、评价、批次等资源接口仍可能需要受控ID、前置资源、身份或业务规则。缺少
  这些资料时留在待补充清单，不猜ID、不用HTTP200代替内容核验。

## 已修正的操作问题

| 问题 | 当前行为 |
| --- | --- |
| 首次读取默认勾选所有受支持接口 | 先建议无需准备资源的读取接口与明确识别的登录；写入和资源依赖接口由用户选择。 |
| 登录字段需要逐项手配 | 文档能唯一识别登录时建议账号字段、Token位置和凭据变量名，仍需用户核对；注册不能因为返回Token就被当成登录。 |
| 默认身份是admin，接口卡却显示匿名 | 卡片显示与服务端相同的有效默认身份。 |
| 登录密码被当普通参数反复提示 | 登录使用凭据变量，隐藏重复的账号密码参数框；清楚说明本机配置及重启要求。 |
| 更新建议重置已有配置 | 更新按钮保留已有名称、输入、断言、身份、地址和选择；新增接口默认未选，不自动扩大授权。 |
| 大段不支持提示挤满页面 | 收进可展开的列表，保留原因与接口数量。 |
| 不清楚隔离环境是什么 | 说明需专用测试数据，本机地址不等于数据库隔离，勾选不会自动创建环境。 |
| 只有状态码也容易看成业务测试成功 | 配置、任务结果和单场景报告均明确提示“仅检查HTTP状态，未检查响应字段或业务内容”。 |
| L3未核验却显示红色失败 | 模型设计模式显示灰色“未独立核验”；实际自然语言校验失败仍显示失败。原报告字段不改。 |
| 真实HTTP报告带内存Demo清理默认文案 | 新报告默认不推断清理结果；仅含读取与登录的已验证计划明确标明无业务数据需要清理。旧报告原文保留。 |

## 格式规则的范围

支持有界的文字候选、字母/数字字符范围及单原子长度限制，以及简单候选分组。
任意嵌套正则、回溯引用、环视或超出预算的规则仍明确拒绝，不静默忽略。JSON Schema的
pattern默认匹配子串，不擅自改成全串匹配或枚举；依据为[官方字符串规则](https://json-schema.org/understanding-json-schema/reference/string)。
旧scalar-discovery-v1目录仍保持原保守边界，历史候选分母和评分不跟随新通用接入能力改变。
