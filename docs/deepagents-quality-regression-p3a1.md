## 冻结消融

在 P3-A 的 `9cb8715` 归档上只注入 A/B/C/D 开关。A 关闭两项，B 仅开 Skills，C 仅开 Context 增强，D 两项都开。关闭 Context 后重读生成完整有界视图，保留 P2.1 的历史工具清理、正式报告分页、预算及证据机制。其余配置相同，包含 16 次模型调用、30 次业务请求、420 秒和 ecnu-max。同一初始批准目录，每轮独立靶场。实现和启动方法见 [消融入口](../scripts/run_p3a1_ablation.py)。

## 实现边界

- 首次正向设计使用已批准的实例结构。运行前校验完整槽位，模型无法声明任意资源引用或改写策略。编译器仍对完整提案的显式策略、字面量和引用进行拒绝校验。拆分的真实执行用例仍经原 DSL 验证、Executor、断言及资源凭据流程。
- Agent 调用分组携带备注时继续采用原始 Focus 范围。一轮相同拒绝后要求新约束。候选若返回零请求，工具不会称已取得执行证据。
- 保留基础运行时、Skills 和 ContextEditing、失败回读、旧报告和专门 CI。业务 API 使用原入口。上线前负向义务仍是原先的批准策略，没有改断言、靶场和预算。

用量按任务账本统计，包含 Focus、Design、Agent 和附属模型活动。上线前账本和设计／Agent 分项差 514 Token，分项只报告可核对下界。四轮再次读取为 0、1、0、2，前批为 1、1、1、2。四轮均按需加载正确 Skill。上线前正向设计请求 3,474 字节，前批全量设计两次在派发前拒绝。新轮测量了 7 项正向和 2 项负向，仍有 22 项未测。功能和调查均未覆盖 Focus 排除的 `readAvailability`，所以这两轮的成本下降和完成不能当作完整复现故障的证据。上线前保留 `readAvailability` 的实际 503 并判为 `ASSERTION_FAILED`。

删除回归首个设计因 `DESIGN_REQUIRED_ORDER_INSTANCE_CONFLICT` 被拒，后续预检有一例 `DESIGN_ABSENCE_PRECONDITION_MISSING`。最终用例按同一资源实际完成 201、200、204、404。该位置走既有回退和补测路径，不能把成功全部归于新设计格式。功能、调查、上线前首轮使用新槽位格式。本批无 `PLANNING_INSTANCE_UNBOUND`。模型调用仍在两个目标达到 16 次。

四轮靶场终态存量均为零，共 7 份 `CLEANED`。上线前一次获批负向 POST 得到预期 422，无创建凭据。当前完成判据保守计为 `CLEANUP_UNPROVEN`，仍为未完成。没有从存量或 422 推定清理成功，没有观察到未知写重放或未授权调用。部分用例使用了独立资源重复执行前置，仍有成本优化空间。

保留首批候选 `.eduwork/runs/p3a1/final/`。功能的嵌套请求遗漏 `options`，预检拒绝为 `OPENAPI_OBJECT_FIELDS`。删除位置 Focus 只将删除映射为请求实例，早期修复未补齐创建及回读，因而 1/1 仍不完整。随后中止该批和正在运行的全量检查，保留已产出记录。最终版本用真正的嵌套对象 schema 在设计时声明必填字段，缺失时返回结构化错误，并在唯一批准来源可证明时投影缺失的创建前置。最终四轮独立运行记录在 `.eduwork/runs/p3a1/final-v2/`。

## 验证及后续

完整离线回归：2,794 个测试均得到终态。2,778 通过、15 跳过、1 个保留的 strict xfail、零失败或错误，源码指纹一致。Ruff 和 Git 差异检查通过。独立 Deep Agents 环境加载相同冻结源码，专项及 Web/CLI 兼容共 118 项通过，包含工具越界、预算、取消、同资源缺失检查和未知写状态。GitHub 专项配置保持原样，远端状态见 [GitHub Actions](https://github.com/mofengyan595/agenttest/actions)。

进入 P3-B 前，应在冻结的新样本中重复测量失败位置和无法在 30 次请求内完成的负向批次。对 Focus 拒绝、运行时预算、未完成义务分别评估，并继续保留失败、未知用量及清理状态。原始证据在本机 `.eduwork/runs/p3a1/`，公开核对数据见 [本轮汇总](evidence/deepagents-p3a1/summary.json)。
