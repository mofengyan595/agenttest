# 统一验收与演示

先用一个命令检查现有功能，再按证据说明适用范围。统一结果表示固定回复和确定性引擎符合既有预期，不代表模型成功率、独立评测成绩或任意项目可靠性。

## 从新目录复现

在仓库根目录使用已有 Python 3.11 `.venv`，需要锁文件中的 agent、mcp、dev 可选依赖；安装说明见 [README](../README.md#快速复现)。入口不安装依赖，不读取模型配置，没有真实调用开关。

```powershell
.\.venv\Scripts\python.exe scripts/check_delivery.py --output runs/delivery-new
```

Linux 使用 `.venv/bin/python`，其余参数相同。输出必须是新的、Git 忽略的仓库 `runs/` 子目录；再次执行应换一个新目录。运行期间保持源码、样例和 Git 状态不变。每项子检查主等待上限 600 秒，超时尝试终止本轮启动的进程树并保留输出，无自动重试；失败继续记录其他独立检查，源码变化则停止后续执行并保留未执行位置。

退出码 0 且 `verified=true`、`verified_checks=scheduled_checks=9` 表示九项全部符合预期；退出码 1 表示验收未通过，2 表示入口或输出目录错误。缺少 Agent/MCP 依赖会保留失败，不会把不完整运行算作成功。

| 检查 | 本次执行内容 | 预期 |
| --- | --- | --- |
| project-courses / project-tickets / project-petclinic | 三份本地配置预检；课程、工单使用临时合成凭据 | 三项 ready，模型／HTTP 均为 0；不代表实际服务就绪 |
| showcase | 原五种演示：正常、故障、只读调查、Java 格式 Mock、MCP stdio | 五项 verified；故障报告保留 ASSERTION_FAILED |
| portability | 两个自建业务域，同一通用规划入口；Fake 和模型 Mock 各 15 项 | 正常 12、指定故障 10、执行前拒绝 8，共 30 个位置 |
| json-literals | J804／J805 固定结构化回复，同计划正常／故障配对 | 生成 2、正常对照 2、指定故障检出 2；Token 为 SIMULATED |
| fixed-regressions | 三份公开固定 pytest 包，在全新正常／故障目标运行 | 正常 3 passed，故障 3 failed，原业务断言不变 |
| portability-archive / json-literals-archive | 重新核对本次封印的快照和报告 | 分别冷评分 30／6 个位置，零新请求 |

这里的 9 是工具检查项数，30 是跨项目固定响应位置，6 是 JSON 配对位置，三者不能相加为独立模型任务数。故障按指定断言检出才符合验收，不以任意错误替代故障证据。固定 pytest 的故障进程退出码 1 是预期现象，由原验收器核对报告后才返回成功摘要。

## 看什么结果

先打开输出目录的 `summary.md` 看各项状态，再用 `results.json` 定位失败项。`freeze.json` 保存源码身份、固定命令及验收条件；`logs/<检查名>/` 保留子命令摘要、标准输出和错误输出。原报告和封印分别留在 `showcase/`、`portability/`、`json-literals/`、`fixed-regressions/`，没有复制进公开文档。

总入口只复用既有工具，不创建新执行器或评分系统。业务请求使用进程内 ASGITransport／MockTransport；MCP 使用真实 SDK stdio，但目标仍为一次性 mini 服务。真实模型调用、真实 Java 请求、真实数据库写入均为 0。归档核对只检查本次离线记录，不重新执行历史真实试验。

原始运行数据继续留在忽略目录，发布时逐项审阅，不能整目录提交。源码身份和文件摘要用于发现变化，不构成来源认证或新的执行授权。

## 当前能力与限制

| 能力 | 已具备的实现 | 范围或限制 |
| --- | --- | --- |
| 新项目配置 | OpenAPI、TargetConfig、PolicyRegistry、TaskContract；项目入口和只读预检 | 操作员提供并确认业务预期；导入 OpenAPI 不等于自动测试整个项目 |
| 通用规划 | 同一提示选择批准操作／角色／策略；动态资源 ID、有限小数和嵌套对象／数组 body | 现有 OpenAPI 子集、根 body 对象；path/query 为标量，容器内部不混入动态引用；不支持任意认证或业务语义 |
| 执行与断言 | 既有安全执行器、凭据隔离、绑定、JSON／批准 CSV、有界轮询、严格类型比较、分类与脱敏报告 | 写入需隔离授权；未知预期 NEEDS_REVIEW；不自动改断言、重放写入或恢复中断 |
| 回归资产 | 完整验证的普通 JSON 计划经固定可信模板导出 pytest | 不执行模型代码；CSV／轮询暂不导出；目标和策略由操作员另行提供 |
| 调查与展示 | 单次只读调查、MCP stdio、本地只读 Web Console | 调查为 FakeAnalyzer 验证；Web 不提供业务执行；不是生产多租户平台 |
| 第三方接入 | 限定 Petclinic 契约、匿名 GET、列表响应 ID 绑定详情 | 真实证据只覆盖只读；第三方鉴权、写入、复杂流程与自动清理未验收 |

普通 JSON 接入见 [项目配置](project-inputs.md)、[可迁移性](portability.md)和 [JSON 约束](json-literals-20261017.md)。CSV 和轮询沿用原专用任务约束，不能把它们的能力自动外推到任意第三方接口。

## 五分钟演示顺序

1. 先展示四份接入配置与预检，说明模型不能决定目标、凭据和业务预期。Petclinic 在未启动时也能通过配置检查，明确区别配置与服务就绪。
2. 展示 `showcase` 的正常报告，再展示故障报告的 ASSERTION_FAILED 和具体断言，说明发现故障为什么仍算演示验收通过。
3. 展示 `portability` 的课程／工单差异，以及复杂 JSON 对象数组、布尔／整数错误和数组倒序的固定证据；说明这一段没有重新调用模型。
4. 展示固定 pytest 的正常／故障结果，说明计划验证后可成为无需模型的回归资产；最后打开上表中的真实调用记录与失败限制。

演示结束后进入最终审查与功能冻结，优先修复实际发现的缺陷；新第三方写入、正式独立评测或新的架构需求另立里程碑。
