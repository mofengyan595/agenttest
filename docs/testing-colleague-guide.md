# AgentTest 使用说明

当前打开<http://127.0.0.1:18120>即可使用。已准备包裹、预约和48接口目录三个项目，
全部是独立自建隔离服务，不连接用户业务系统。[验收结果和限制](testing-colleague-delivery.md)。

## 先跑一轮

1. 在项目卡片点“开始一轮测试”。重点可以留空，也可直接交代想检查什么。
2. 运行时查看实际进度；缺信息时按具体问题补充，已获授权的独立检查可以先执行。
3. 看结论、问题证据和未测试原因。结束不代表所有业务都正确。
4. 通过的受支持只读场景点“保存测试”，在“已保存测试”点“再次运行”，不再调用模型。

接入自己的新项目，按下面“接入并开始”操作；不必先学习内部格式。

## 需要重启时

服务尚未运行时，在项目根目录、已有 `.venv` 和前端依赖的情况下执行：

```powershell
cd D:\Desktop\project\agenttest
cd web
npm.cmd run build
cd ..
.venv\Scripts\python.exe scripts/start_colleague_lab.py
```

打开 <http://127.0.0.1:18120>。 当前准备好的本地工作区已有包裹、预约、48接口目录三个示例项目，
可直接点项目卡片的“开始一轮测试”，重点可留空；也可用下述文档重新接入。模型读取本机已有 `.env`；未配置时明确阻止执行，
不会改用模拟。启动本地服务本身不调用模型；在网页开始测试后才产生模型调用。
如果18120不是本产品但已被其他程序占用，可以用
`--port 18220 --data runs/testing-colleague/playground-18220` 新建独立工作区。
此时目标端口为18221、18222、18223，须按新地址重新接入；不要沿用18121至18123的旧配置。
已有本产品页面能打开时，直接使用，无需再启动第二份。

## 接入并开始

网页的“项目”页填写项目名称并上传下面的文档，点击“读取接口并配置”。
可以填写并保存简短业务说明，后续任务会复用；它帮助理解项目，不会自动成为执行权限或断言。
确认隔离环境地址、是否允许本轮测试数据写入，以及文档建议的输入、依赖和响应检查。
需要测试错误参数时开启受控异常参数测试。若希望模型或用户指定不同的错误值，另勾选
“允许在同一字段、同类文档约束内变化异常值”；默认只允许已确认的固定错误值。
新增范围仍限制为同一字段、同类文档偏差与原拒绝状态，不能改变断言或扩大接口权限。
明确指定值而尚未授权时，该部分会等待补充，不会换成其他值后算完成。
也可以自然地要求异常字符串的具体长度；系统在已有同类异常授权内准备该长度，仍保留
文档约束、方向和拒绝状态。指定长度当前最多1000个字符；没有变体授权时仅该部分等待补充。

| 项目 | 文档（相对根目录） | 测试地址 | 重点 |
| --- | --- | --- | --- |
| 包裹 | `runs/testing-colleague/playground/documents/parcels.openapi.json` | `http://127.0.0.1:18121` | 嵌套输入、数量边界、动态资源与 CRUD |
| 预约 | `runs/testing-colleague/playground/documents/reservations.openapi.json` | `http://127.0.0.1:18122` | 登录、资源所有者、另一身份权限补问 |
| 目录 | `runs/testing-colleague/playground/documents/directory.openapi.json` | `http://127.0.0.1:18123` | 48 个接口的完整清单、分组、查询参数和局部受阻 |

预约项目展开“配置测试身份”：添加 `owner`，选择账号密码登录，登录接口选
`openSession`，账号、密码环境变量分别填写 `AGENTTEST_TARGET_LAB_OWNER_USERNAME`、
`AGENTTEST_TARGET_LAB_OWNER_PASSWORD`。账号、密码与响应 Token 字段会根据文档建议，
需要调整时从下拉框选择相应字段，不必填写取值表达式。
再添加 `reader`，使用预置 Bearer，环境变量填 `AGENTTEST_TARGET_LAB_READER_BEARER`。
默认身份选择 `owner`。这些只是服务端凭据的名字，网页和测试需求里不填写密码或令牌。
启动器每次生成专用随机凭据，仅传给本次服务进程，不写入文档或日志。

模型超时且未返回用量时，停止新的模型任务并先核对服务端记录。重启或更换目录不能当作用量
已查清。操作者若明确对某一次异常作出例外，必须单独留存授权，原用量仍显示未知；
该例外不适用于后续其他未知调用。此为产品默认规则；本 Goal 的操作者随后明确授权
“以后未知用量也可以继续”，故本轮开发验收可留存授权后开始下一项独立任务。
未知项仍不计作零，也不计入已知 Token 小计；超时请求不会自动重试。

保存后，点击项目卡片“开始一轮测试”。测试重点可以留空；也可以直接交代想检查的内容。
指定流程只执行本次选择的异常检查；开始全项目一轮时，系统可以主动选择已批准的异常场景。
尚未确认的业务预期会具体提问。确认权限预期只保存规则，不发送业务请求；再次提交后才测试。
输入尚未确定时，选择问题下的具体取值，网页会填入补充内容；点击“提交补充需求”再开始。
同一范围内尚未回答的问题会保留；补充名称时，先前明确的日期、座位等输入会继续复用。
权限问题展示访问身份，确认前不发送相关跨身份请求。普通未知业务预期仍需提供可确认的规则，
不会把模型的业务猜测自动当作断言。
依赖该输入的请求会等待，已经完成的证据保留。也可直接用自己的话补充，不必填写内部格式。
需要精确保留名称时，可以自然地写“名称为‘夏季归档’”；其他输入在批准范围内生成。

## 查看与保存

结果同时显示完整文档分母、本次实际请求、检查依据、问题和未测试原因。
明确指定的受控异常检查会单列实际执行数和本轮要求数，不能用正常请求代替。
项目的已批准异常能力另列已尝试数与完整分母，未尝试项目可翻页查看；它不是全部可能
业务场景的分母，也不代表每个值都测过。“模型方案类型”和真实异常执行次数分别展示。
模型命名为异常、却没有执行异常策略的历史场景会明确提示，不能保存为异常回归。
发现不符结果不表示已确认内部原因；只读复核会另列，原始失败不会改写。
在“模型建议与真实用量”中查看本轮调用和 Token。

通过的受支持只读场景可点击“保存测试”，再从“已保存测试”点击“再次运行”。
固定复测禁用模型。显式登录后的只读场景也受支持。
包含业务写入的场景，目前因完整准备与清理控制尚未实现而不开放固定复测。
配置或规则改变后，旧测试需重新确认，不能静默沿用。

关闭启动命令会停止本次启动的服务；项目、规则、任务和已保存测试保留在
`runs/testing-colleague/playground/workspace`。重新启动后可继续查看。
隔离目标的临时资源不跨重启保存，固定复测不得依赖上一次的临时资源。
上传与长异步任务保留在完整接口清单中，当前产品流程暂不执行。

当前通用输入支持对象中的嵌套对象与数组、常见标量、枚举和数值/长度约束。
单个接口的一次计划最多30项顶层输入；这与项目接口数不同，项目会保留完整清单并分组设计。
根请求体数组、查询数组、复杂组合 Schema 和文档未能解析的结构会列出具体不支持原因。
这些范围以接入后的实际清单为准；通过基本响应检查不表示已验证所有业务含义。
