# 组合参数约束与新任务验证（2026-10-14）

## 问题与修改

上一批 P205 在上传步骤同时带 JSON body 与 multipart，原 DSL 在业务请求前阻断。首次失败不修改、不重跑。本轮从操作员批准 Policy 的 closed_arguments／binding_rules 投影允许的参数数量、location、name、字面量类型、引用方式及选择器；同一目录适用于所有任务，没有发送标签或标准路径。

登录参数必须为空；创建课程仅允许 body.name；CSV 上传仅允许 path_parameters.courseId，文件仍由执行器提供；轮询和结果查询仅允许 path_parameters.batchId。重复的参数 Schema 复用定义，使完整输入继续满足原 20,000 输入上界，不扩大额度；这只是避免重复字节，不声称实际 Token 成本下降。

模型回复通过结构校验后，再按同一公开批准目录检查参数槽位。违反约束返回 MODEL_SCHEMA_COMPOSED_ARGUMENTS，不持久化生成值，不修补或重试。本地 DSL／Policy／Intent 仍负责操作授权、身份、资源来源、先后关系和目标完整性，参数结构合法不等于获准执行。普通 generic 与 mini_batch 路径不套用这项组合约束。
