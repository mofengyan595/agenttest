# 接手接口测试的产品里程碑（2026-10-26）

本轮来源为用户在当前 Goal 中的完整要求；取代旧里程碑对本轮相关开发和新模型试验的冻结。
历史评测、失败、成绩和归档保留，不重新计分。现有未提交接入工作是起点，不覆盖或回退。

## 授权与边界

- 使用本机已配置真实模型；允许发送文档、需求与脱敏上下文，凭据不得进入模型或日志。
- 无 Goal 总调用/Token 上限；每任务必须有时间、模型、HTTP、步骤边界，未知用量停止后续调用。
- 允许独立自建回环 HTTP 服务中的专用数据增删改查，不操作用户实际业务写接口。
- 无 branch/worktree、commit/push、CourseInsight 修改、多 Agent、RAG、第二套 Agent 框架。
- 保留现有结构化计划、校验器、确定性执行器、报告、任务服务、SSRF/身份/脱敏保护。
- 不执行模型代码、不放宽失败断言、不重试非法计划、不自动重放写请求。

### 2026-10-26 后续用量授权

用户在本 Goal 中明确补充：“以后未知用量也可以继续”。此指令取代本轮开发验收的
未知用量跨任务停止要求，允许后续独立任务继续，不必逐次请求例外。
原始 UNKNOWN、超时、失败和空 Token 必须保留；只汇总已知 Token，不能声称总用量已知。
当前超时任务仍结束，不自动重试；后续新任务继续遵守各自的模型次数、HTTP、步骤与时间边界。
每次解除持久停止记录均引用此授权，独立记录受影响的调用，不更改原始用量。
此授权仅适用于本 Goal 的开发验收，不更改产品面向其他操作者的默认停止规则。

## 顺序与检查点

1. 完整接口清单、分组/分批、就绪原因与具体补问，解除已选 30 接口限制。
2. 真实模型理解自然需求与设计测试；有界输入生成、文档与已确认规则的依据、未知预期待补充。
3. 实际 HTTP、实际事件进度、失败证据、受控只读调查、完整覆盖与任务完成分开报告。
4. 项目/当前测试/结果/已保存测试页面；持久规则与上下文、固定复测及配置变更失效。
5. 针对检查、全量离线、前端/构建/E2E、桌面/手机、启动和操作材料。

### 开发检查节奏（用户要求提速）

日常修改先运行覆盖变更的最小有效检查，使用 `scripts/check_dev.py --area product`、
`--area contracts` 或 `--area tasks` 查看并执行明确范围。每次保留耗时和失败结果，
不得把局部通过表述为完整验收。只改文案时不重复后端历史评测与完整浏览器排期。
后续验证提速提供更小的 `focus`、`intake`、`execution` 范围；较大离线检查可使用
`--jobs 3` 分批并行，历史耗时只用于安排分组，每份选中文件重新检查且只分配一次。
每批使用独立目录，保留日志、错误和实际墙钟；不并行更改真实业务请求或重跑历史模型排期。
核心改动稳定后集中执行一次全量离线和完整浏览器检查；后续仅在新增改动或未解决失败影响
对应范围时复验。最终三个项目、三轮真实模型和既有安全验收要求不缩减，不重开旧付费排期。

## 新验收

正常网页接入至少三个新结构项目，其中一个 40+ 接口，不增加业务适配器。
涵盖嵌套对象/数组、路径/查询、动态依赖、隔离 CRUD、身份、确定故障、未知预期、不支持项。
真实模型设计与自然需求、真实本地 HTTP、保存/无模型复测，以及刷新、重启、重复、取消、变更、部分受阻。
最终任务另行预冻结、未用于调试，三轮均保留首次尝试、失败与未执行项；修改后使用新版本记录。

证据分别标明离线、模拟、真实模型、自建真实 HTTP；不声称实际业务、广泛泛化、独立人审或人工节时。

## 起点核查

当前 generic_intake.build_generic_project 限制 30 已选接口；GoalCatalog 也限制 30。
discovery_schema.fields 拒绝嵌套输入，但底层 request_validation 已能校验嵌套对象与数组。
通用接入固定 literal enum；自然语言仍用别名识别。ProjectIntake 已持久保存版本与确认，TaskService
已有串行任务、重复提交/取消/重启中断和版本门禁；SavedTests 已支持持久保存与真实只读复测。
