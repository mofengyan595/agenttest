# 项目接入与网页使用

2026-10-26：正常入口已改为真实模型与通用接入，请使用[新版产品说明](product-intake-guide.md)。
以下保留专用模拟体验的操作；它不代表正常产品模式或真实模型验收。

本轮提供三个入口：**项目 → 测试助手 → 测试记录**。本地体验使用模拟规划器和工单、课程两个
专用内存目标，不需要模型密钥、Docker 或业务服务。每次测试产生独立资源。
工程流程通过不代表真实模型理解质量改善，也不代表独立使用者已经认可体验。

## 本地启动

使用仓库自己的 Python 3.11 环境，安装既有 Agent 依赖；前端使用 Node.js 22.12+。
首次环境准备仍按 README 的安装说明进行。没有新增运行依赖。

先构建网页（已有 node_modules 时不需要重复 npm ci）：

```powershell
Set-Location D:\Desktop\project\agenttest\web
npm ci
npm run build
```

之后只需在仓库根目录运行：

```powershell
.\scripts\start_web.ps1 -Demo -Data runs/web-workspace
```

打开 [AgentTest 本地网页](http://127.0.0.1:18012)。这个启动方式在同一服务上提供网页与 API，
不必再启动 Vite。端口被占用时使用 `-Port 18013`，并打开启动输出中的对应地址。
服务仅监听本机回环地址；Ctrl+C 关闭。服务重启不会恢复未完成请求或自动重放写入。

网页源码改动后重新执行 `npm run build`，刷新页面即可读取新的构建。
纯后端改动需要重新启动服务。

## 接入一个新项目

1. 在“项目”填写名称，上传 OpenAPI 3.0/3.1 JSON 或 YAML，最大 1 MB。也可展开后粘贴文本。
2. 选择服务端已经授权的环境与业务配置。首次体验可选择“工单 · 内存模拟目标”或“课程 · 内存模拟目标”。
3. 核对身份别名、准备状态、操作及业务预期。查询的初始状态与“关闭后查询”的状态会分别列出。
4. 确认适用的行为与预期，点击“保存并检查接入”。确认记录绑定操作者会话、配置摘要和时间。
5. 状态变成“可提交测试”后，从项目卡片进入测试助手。刷新和重启后仍可读取已保存登记。

用于本地体验的接口文档：

- 工单：`examples/trusted-testing/projects/tickets/openapi.json`
- 课程：`examples/trusted-testing/projects/courses/openapi.json`

这些文件仅提供上传资料。网页保存会创建新的 `web_…` 项目身份与配置版本，
不会把选择一个旧登记文件当作网页新建，也不会覆盖服务端授权源文件。

| 页面状态 | 含义与下一步 |
| --- | --- |
| 接入草稿 | 文档已保存，尚未选择服务端授权配置；继续准备环境、身份和业务映射。 |
| 待补充 | 已选择配置，但仍缺确认、凭据或文档匹配；按缺失项继续配置。 |
| 可提交测试 | 配置检查通过，可以发起支持范围内的需求；尚未证明环境可达或业务通过。 |

当前引擎只支持已有授权配置覆盖的项目。任意有效接口文档都可保存为草稿，
但文档的解析结构必须与所选配置一致才能执行。全新业务域仍需要操作员在服务端接入操作、
角色、资源关系及业务预期；普通使用者无需逐题编写 JSON、DSL、TaskContract 或断言。

接口文档和模型建议不会产生执行权限。网页不能新增任意目标地址、扩大操作许可、设置密钥或
批准新的业务断言。需要服务端账号时，页面列出缺失身份及环境变量名称；不显示凭据值。
操作员补齐启动环境中的凭据并重启服务后，再点击“重新检查”。

操作员配置的登记入口为 `AGENTTEST_PROJECTS_FILE`，详细结构沿用 [自然语言入口](nl-entry.md)。
网页确认只表示本地操作者认可已经展示的现有规则，不是独立人审、生产批准或文档自动转为可信规则。

## 交代测试任务

选择项目、输入需求、点击“开始测试”。示例按钮只填写文字，不执行。
可使用以下受支持表述：

- 单接口：`测试创建工单接口`
- 工单流程：`创建工单，关闭工单，查询工单，其他用户不能读取工单`
- 课程流程：`创建课程，查询课程`
- 项目范围：`测试工单项目核心接口`

“更多测试范围”可包含已有参数边界和批准负例。项目原有策略要求审阅时，会显示具体范围及
“确认此计划并执行”；其他已有授权任务自动推进。动态编号、登录及资源依赖由原执行链处理。

页面分别说明规划来源与执行目标。模拟模型、真实配置的模型、内存模拟目标及授权测试环境
不能混用。真实模型未配置时提供操作员指引；本轮没有进行真实模型调用。

进度来自服务端保存的规划、校验、执行与报告事件。没有计时动画推测工具动作，
也不展示模型内部推理。手机提交后会滚动至当前任务的进度与结论。

例如输入退款金额之类尚未支持的业务要求，系统会指出无法核验的部分、为什么缺少规则，以及
需要补充的接口行为、身份和明确预期。点击“补充澄清”产生新的受控任务，保留原记录并共用剩余预算。
没有隐式重试、失败计划修复或写入恢复。取消只停止后续动作，不承诺回滚已发请求。

## 读结果和保存测试

结果先说明本次需求是否完成，再列出实际接口步骤、不符合预期的字段、预期值与实际值、
未执行部分和下一步。项目范围保留全部接口、场景及断言分母；部分检查通过不代表项目全部完成。
运行中尚未形成的覆盖结果不会显示成最终覆盖。

| 中文结果 | 解释 |
| --- | --- |
| 检查通过 | 已执行的确定性检查通过；另看整个需求是否满足。 |
| 结果不符合预期 | 实际响应与已确认断言不一致；查看请求和检查依据。 |
| 环境错误 | 传输、环境或预算异常，不能直接认定为接口缺陷。 |
| 工具错误 | 计划、依赖或工具失败；保留未执行部分。 |
| 需要补充信息 | 业务预期、配置或语义尚不能确认；不猜测通过或缺陷。 |

计划合法、操作授权、需求符合、业务结果、任务完成与流程结束继续分别记录。
“实际执行过程”“测试范围与预算”“逐项检查与未完成原因”可以展开；指纹和原始状态留在详情中。
完整报告保留四层校验、业务步骤、尝试和模型诊断。模型建议与确定性结论分开，证据不足保持未确认。

完整通过且受支持的普通 JSON 场景可以下载并保存固定回归包。保存后，“测试记录”会列出资产；
专用合成环境支持“再次运行固定测试”。每次创建新资源，调用既有固定回归执行器，模型禁用，
不延续原 HTTP 会话。再次运行的 PASS 是固定计划检查通过，`task_satisfied=null`，不冒充重新理解自然语言。

包内含固定模板 pytest、计划数据、manifest 和说明，不包含凭据或目标授权。
命令行运行需要操作员提供原有 `agenttest_regression_runtime` fixture，再运行
`python -m pytest <回归包目录> -q`。下载本身不等于已配置这个 fixture。

上传、轮询、读取重试、失败或待审场景不能导出；页面显示原因并隐藏无效导出按钮。
配置变化后，旧任务不能继续启动，旧资产不能再次运行。重复提交保留同一任务，取消和中断不自动恢复。

## 保存位置与当前限制

- 默认数据在 `runs/web-workspace/`：项目接入 SQLite、任务 SQLite、报告和已保存固定回归。
  网页不能提供文件路径，也不能写出该服务配置的目录。
- 项目更新采用版本检查；服务端授权文件变化会使旧业务确认失效，需要重新核对。
  解析缓存逐次核对源文件内容，不以旧缓存维持已经变化的授权。
- 本地任务会话仍沿用现有一小时期限。会话有效期间，刷新和服务重启保留同一所有者的任务与资产；
  会话过期或浏览器清除 Cookie 后，旧任务不向新会话开放。已下载回归包和服务器报告仍保留，
  公共脱敏报告可从报告页读取。不要把重新建立会话当作自动恢复原请求。
- 尚未保存的通过场景只有内存导出上下文，服务重启后无法首次导出；已经保存的资产可重新读取。
- 网页再次运行固定测试只支持专用合成环境；真实环境的审批、账号、授权及外部写入不属于本轮验收。
- 浏览器和自动化检查属于代理自检。真实用户体验、独立人审、时间收益和真实模型理解改善均未验证。
