# 混合规划剩余缺陷修复（2026-11-07）

开发基线为当前 master 的 `00f570b77524bfd9d70dcbe165e82f1e6233ac5e`。本轮只调整资源见证与权限问题的来源约束，复用既有的需求对账、策略审批、依赖阻塞和确定性执行流程。

N06 第 1 轮的归档记录了 `FOCUS_REQUIREMENT_RESOURCE_INVALID`、空 `diagnostic.fields` 和模型输出摘要，没有保存被拒绝的模型原文或解析结果。因此无法从历史记录确认当时选中了哪个资源，或具体命中了哪个校验条件。代码中可以独立复现两处缺陷。

- 原来的 `requirement_schema` 向每个原文分项提供全部已配置固定资源引用，包含后续独立读取的资源。相邻的待审内容检查也能选择缺少原文依据的引用。
- `validate_requirement_links` 对固定资源引用强制要求 `disposition == required`。即使资源、身份、固定路径和原文见证均正确，只要内容规则缺失而被标为 `needs_review`，整个聚焦结果就会被拒绝，独立读取无法进入设计。

N02 的归档保存了完整聚焦结果，可以直接核对。版本读取的原文为“另获取 Gitea 版本号”，动作身份为 `null`，模型却以 `archivist` 为主体提出版本权限问题。生成候选时，`select_focus` 将尚无该接口专属角色规则的项目身份列入 `permission_question_roles`。匿名已批准规则不属于非空身份的已确认访问规则，因此这个候选仍然存在。原校验只检查操作已选、身份在候选中、问题引用了任务原文，没有要求问题身份属于该原文分项的动作。问题随后被 `product_tasks` 保存、传给设计器，并使最终完成状态为假。
