# 收尾审查与功能冻结

本轮按统一验收后的里程碑审查近期接入配置、结构化 JSON、固定回归导出及交付入口，并抽查原 Workflow／Executor／报告文件边界。只修复实际复现的问题，冻结范围是本地研究与演示功能；第三方复杂业务、正式独立评测和生产交付仍各自需要验收。

## 修复的实际缺陷

在 `204923e` 上，超时回收忽略 taskkill 的非零退出码、进程组终止异常及再次等待超时。受控假进程测试复现：第一项回收未确认后，后八项的执行函数仍被调用，无法清楚表示残留进程风险。首次测试为 **1 failed、12 deselected / 2.94s**，原失败保留。

现在 [delivery.py](../src/agenttest/delivery.py) 将未确认回收标为 `CHILD_CLEANUP_UNCONFIRMED`；总入口 `cleanup_unconfirmed=true`、`verified=false`，后续位置全部保留为 NOT_ATTEMPTED，不重试。普通检查失败仍可继续其他独立项，源码变化仍停止后续项。

子进程输出直接写入新的私人文件，避免清理失败时等待仍被后代持有的输出管道；根进程等待和回收等待均有上限，不使用 Popen 上下文退出时的隐式等待。回收未确认时只读取最多各 1 MB 的部分输出，读取失败也不能把清理状态改成已确认。原过程输出文件保留，后续不覆盖它们。

Windows 根据本轮 PID 的 taskkill /T /F 结果及根进程退出结果判断回收。POSIX 只尝试终止本轮进程组：固定 MCP SDK 的 stdio 子进程会另建会话，进程组退出不足以证明全部后代退出，因此超时按未确认处理并停止。该标记表示需要操作员检查本次残留进程，不表示实际证明存在残留，也不声称实现了通用进程沙箱。

过程管理语义核对了 [Python 3.11 subprocess 文档](https://docs.python.org/3.11/library/subprocess.html)和 [Microsoft taskkill 文档](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/taskkill)。SDK 会话行为来自本机锁定的 mcp 2.3.0 `mcp/client/stdio.py`；没有修改 SDK 或增加依赖。

## 门禁审查

| 路径 | 本轮核对的具体边界 |
| --- | --- |
| 项目接入 | 项目文件只引用本地相对路径；固定输入摘要；配置预检不生成策略、写入许可或模型设置 |
| 规划与意图 | 模型回复经有界 JSON、类型与来源校验；TaskContract 校验操作／角色／参数／引用；无可靠意图验证不执行 |
| 执行 | 唯一 Executor 复核策略；目标 IP 固定、关闭环境代理及重定向；run 状态隔离，发送前保存证据，不恢复写入 |
| 固定回归 | 仅接受完整通过且来源匹配的计划；Python 为固定可信模板，参数单独保存；运行重新核对配置与断言 |
| 报告 | 文件和祖先路径固定，拒绝链接／重解析点；原脱敏及单写者保护保留 |
| 交付入口 | 九个固定检查位置；子检查退出码和摘要都要符合预期；源码变化或清理未确认均停止，失败位置不删除 |

这些是本轮审查范围和确定性检查，不是全项目无缺陷证明或独立人工评测。没有改变模型提示、旧任务、批准断言、SSRF 保护或测试禁网夹具，没有 CourseInsight 代码修改。

## 验证与冻结范围

修复后的交付专项 **18 passed / 2.71s**，包括三类回收失败、部分输出读取失败、Windows／POSIX 分支及原九项结果保留。故障由测试注入，没有在操作系统制造不可终止进程，也没有实际等待 600 秒。

扩大回归 **174 passed、8 skipped / 65.33s**。单独核对跳过项：七项因本机缺少符号链接创建权限（WinError 1314），一项仅适用于 POSIX，不计为通过。完整入口 **9/9 VERIFIED、source_unchanged=true、cleanup_unconfirmed=false**；固定 pytest 正常 3 passed、指定故障 3 failed，两份归档分别冷核对 30／6 位置。原完整验收进程中断，只留下六项完成记录，保留后用新目录重新完成整轮；不将部分结果算成通过。

Ruff、pip check 与五份文档的本地链接检查通过。本轮真实模型、Java、数据库写入均为 0，运行证据保留在忽略的 `runs/final-review-20261017/`。未重复本机全仓或 Web，最终提交的六组 CI 随交付核对，结果见[进度](progress.md)及交付说明。

冻结保留：四份可信接入配置、限定 JSON REST 与批准 CSV／轮询、现有规划与安全门禁、确定性断言、脱敏报告、固定 pytest、只读调查／Web、MCP stdio 和[统一演示](unified-acceptance.md)。已有真实小样本记录继续单列，旧失败与未执行位置不变。

继续公开的限制：新版本 Java 和 Java batch 未适配；第三方认证／写入／复杂链路与自动清理未验收；真实模型失败调查、生产审批、多租户、写入恢复与独立大样本评测未完成。开发样本仍 UNREVIEWED，独立审核数没有增加，正式 Eval v2 门禁不变。

冻结后的下一步是维护：仅为可复现缺陷、安全修复、依赖兼容或明确的新需求开工作项。新增功能和新的第三方写入另立里程碑；求职展示先使用现有五分钟演示，不继续旧题调参或堆叠架构。功能冻结是交付范围约定，本轮不创建 Git tag、分支或不可变发布。
