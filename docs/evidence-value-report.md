## 为什么有证据仍会错

旧模型的9次错误弃权有明确finish记录，不能归咎工具没有返回；旧菜单缺少工具操作与资源关系，
检查虽脱敏但已有批准语义，原提示未保证模型遵守。新候选补充关系、完整动作和结束规则后，
支持类结论改善。这是组合干预的开发证据，不能单独证明某一提示或Schema的因果贡献。

新的失败证明“让模型看懂字段”仍不足以保证它执行全部条件：

- EV10三轮B：HTTP检查未通过，字段缺失重复失败不能支持回读不一致；模型仍选择该症状。
  第一轮 `reports/f41e1209140f421f85c0bc226dc08b94/report.json` 的最后public_context中
  http_checks_passed=false，proposal仍为PERSISTENT_READBACK_MISMATCH。
- EV11三轮B：原失败是PATCH，调查为GET，不满足同操作条件；最后关系明确
  same_operation_as_original=false，模型仍断言。第一轮记录
  `reports/4e1e23f4546d49189fa34d832f036e2e/report.json`。
- EV12第一轮B：复核没有重复失败字段，repeated_failed_checks为空，仍作持续不一致断言。
  记录 `reports/ed7e1f57ce094ab98438622f8375e006/report.json`。

这些提案的枚举与合法引用已保存，可以确认模型选了什么；不猜测它未保存的内部推理。
7次均为有合法双引用但证据关系不充分，不能称为“只差引用格式”。引擎均保留NEEDS_REVIEW，
未将其升级为可信症状或修改原ASSERTION_FAILED。
