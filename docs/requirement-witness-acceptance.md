# 需求见证与接入验收规范

起始基线 `4b5c24ff5df30fafb66468792530efe5a33a40f0`。先验证遗漏、数值来源、动作见证、资源关联、多余追问及局部阻塞的离线反例，再逐步验证接入和真实流程。11 月 5 日的原文和结果仅用于审查与开发回归。

## 样本隔离

- 正式任务从独立验收目录读取。运行端只向工作台提交原文和操作员已确认的项目配置。预期步骤、精确输入、断言、禁止发送的请求、可执行性标签留给评测器，运行端不传入模型或产品代码。开发测试只能使用独立的构造题和历史回归。
- 目标为本机隔离的实际 API 服务。冻结前用公开或已授权读取核验版本、夹具、契约及配置。只读套件禁止变更目标业务数据，必要登录单列。额外写入须限定在为验收新建且有归属证据的隔离环境，并沿用原有清理策略。
- 冻结每条原文、配置摘要、预期、顺序、模型名称、单任务预算和两版源码。计划 24 条新需求，覆盖多接口、边界、身份与资源、局部阻塞、混合需求，包含新业务域。同一条原文的两版使用同一目标和配置。计划每版两轮，轮换先后顺序。每位置只提交一次。已消耗位置不更换题目，也不重放。
- 只使用配置好的真实模型，按现有机制限制预算，无法确认用量时停止后续调用。后续位置保留为未执行。保存源码 SHA、冻结摘要、模型记录、任务终态、逐请求记录、检查结果和耗时。配置错误、登录限流、目标超时和模型故障按位置单独保留。

## 判分

首次完整执行按原文逐项匹配实际请求、身份、参数、状态及检查，规划过的步骤不能代替实际记录。已正确阻塞与完整执行分别计数。每条未完成需求必须有可定位到原文的原因或待确认项，缺失则计为静默漏项。错误拒绝的分母为已知合法且具备条件的任务。越权执行以实际尝试发送为计数。逐条检查追问是否已有明确答案，同时报告追问数、模型调用、已知 Token、UNKNOWN 次数、端到端耗时及重试。

同一开发者编写和核验的实验标注为开发验收。第三方独立审查只有实际进行后才计入。验收缺位一律保留分母，单次成功与旧版异构实验均不能替代两版同规则对照。
