## 已确认的问题与诊断限制

五条结构失败只留下安全诊断及输出摘要：P003/P004/P007 位于 `steps.4`，P005 位于 `steps.6`，P011 位于 `steps.3`；序号从零开始。代码核查确认，该诊断对应步骤的跨字段业务校验，约束包括操作与策略匹配、批处理限 alice、CSV 与轮询引用必须用于对应操作。

给服务的 JSON Schema 包含单字段类型和枚举，没有表达这些跨字段条件；约束仍由本地校验器强制执行。现有七条批准的正常固定草稿均能通过同一草稿转换和 Scenario 校验，说明该路径可以接受正确计划。真实失败表明模型没有可靠遵守完整组合约束，但现有证据不能排除每一项适配边界问题。

原始模型回复没有持久化，不能从摘要恢复具体字段值，也不能断言五条失败都是同一种 CSV／轮询错误。P006 确认违反认证顺序；P008 确认违反策略依赖；P009/P010 的脱敏计划证据确认模型给出了部分计划而没有主动拒绝。不得靠补登录、补步骤、改引用、删目标或放宽断言追认这些失败成功。

下一准确里程碑：先为组合步骤校验增加不含生成值的细分诊断，确定失败属于操作／策略、角色、CSV 还是轮询约束；随后在新的未用任务上验证约束表达和角色依赖规划。保留本轮原始成绩，不在这十六题上循环改提示、重跑或调分。陌生项目验证仍需固定真实 REST 项目版本、可信业务配置及隔离环境。
