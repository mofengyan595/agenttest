## 同一新评分协议

版本 `nl_product_v1_model_proposals_v1`。两个版本均按其实际输出评分，不能先把基线输出
用新规则虚拟纠正后再计成基线产品结果，也不能把规则补足计入模型答对。

- 规划分别记DSL合法、策略授权、意图全部满足、操作/角色/策略组合正确；偏序和来源继续校验。
- 正常完成要求完整业务步骤、所有断言PASS、原意图与task_satisfied为true。请求前安全拦截计失败。
- 指定故障要求合法/授权/意图通过，且原业务ASSERTION_FAILED来自指定接口与指定断言。
  任意其他失败、流程结束或规则拒绝错误建议都不能代替指定故障检出。
- 受支持故障的产品目标还要求实际输出正确症状和完整双引用，按实际观察重新核验。
  基线读原feedback结果，候选读独立trusted_symptom；两者使用同一规则范围核验。
- 证据不足的产品退出要求业务指定失败已检出、实际规则无支持、产品明确NEEDS_REVIEW /
  EVIDENCE_INSUFFICIENT、无伪造引用、反馈正常终止且用量已知。模型错误建议被拒绝可以形成
  保守产品退出，但不记模型主动答对。工具错误/超时/未知用量不能冒充完整退出。
- 模型结论、支持建议、主动弃权、不当断言和工具选择单列；规则支持时模型主动弃权仍是漏诊。
  采纳的模型建议也须符合新规则的同资源/同策略等边界，不直接复用旧分数。
- 工具选择记录相关读取、能形成证据的读取，以及与相同公开上下文中确定性建议的吻合。
  这只是行动归因观察，没有第三组真实反事实实验，不宣称模型额外价值或节时。
- 按位置保存完整耗时、工作流耗时、调用、输入/输出/总Token；Mock用量为模拟，真实用量另表。

规则仅报告ACCESS_BOUNDARY_VIOLATION和PERSISTENT_READBACK_MISMATCH两种可观察症状。
持续回读必须同批准策略，不能把open与closed的不同预期混作重复证据；不足则NEEDS_REVIEW。
原业务Outcome和断言不改变。没有真实使用者计时，不报告人工节时；没有人审，不代签。
