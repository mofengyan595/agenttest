# 三轮跨项目稳定性验证（2026-10-16）

## 固定范围

本轮保持规划提示、执行器、策略校验与意图检查不变，冻结四条新开发任务，各重复三轮。
每轮轮换任务顺序；后续轮次在第一次调用前已列入计划，不是失败后补跑。
不改题、预期、角色、参数来源或预算来追求通过，不覆盖历史成绩。

| ID | 任务 | 目标与隔离 |
| --- | --- | --- |
| P501 | 创建课程，核对创建者读取、另一角色拒绝访问、CSV 批处理与两条结果 | 新建进程内 mini 服务 |
| G501 | 创建新主题工单，关闭并再次读取状态 | 新建进程内工单服务，预置 Bearer |
| F201 | 查询列表，绑定实际第 2 项 ID，再读取详情核对 ID | 固定版本 Petclinic，仅 GET |
| F202 | 查询列表，绑定实际第 4 项 ID，再读取详情核对 ID | 同一隔离只读 Petclinic，仅 GET |

新文字与列表位置属于已有受控任务族，不能称为独立泛化题集。每次课程／工单执行
使用全新状态和临时凭据；Petclinic 的只读操作复用同一全新 H2 实例。
同项目内所有轮次使用相同契约、完整批准目录与预算。F201／F202 也共享整个目录，
不按题目裁剪选项；模型看不到 TaskContract requirements、标准计划或评测标签。

## 记录与复核

完整分母固定为 12 个位置。每条保留轮次、结果、独立计划证据、脱敏报告、调用次数、
耗时与已知 Token；服务失败或用量未知时停止后续真实调用，剩余位置标记未执行。
失败、未执行均保留在每题三次的分母内，不能只报成功题；未知用量不当作零消耗。

按每题列出三次结果和全部三次成功标记；耗时只列最小／中位／最大，不用三次样本
估计生产 P95。课程组合、工单和真实第三方分别解读，不合并为任意项目成功率。
离线 Mock 用量明确为 SIMULATED，不计为真实模型或 Java 证据。

归档封印清单后，可在不调用模型、不启动目标、不发 HTTP 的条件下重新评分。
伪造摘要、漏轮次、重复运行 ID、改计划／报告证据均应被拒绝。
保持 DEVELOPMENT_ONLY／UNREVIEWED、human_reviewed=0、formal_eval_v2_score=null；
本协议没有修改正式独立评测的审核与锁定门禁。

## 离线复现

```powershell
.\.venv\Scripts\python.exe scripts/check_stability.py --output runs/stability-offline
.\.venv\Scripts\python.exe scripts/check_stability.py --verify runs/stability-offline
```

输出目录必须是仓库内新的 runs 子目录，已有目录拒绝覆盖。命令只使用固定回复和
内存／Mock 目标，没有真实模型或 Java 开关；图执行需要现有 Agent 可选依赖。

### 工单失败与已确认缺口

R2-G501 生成的步骤多出了 listTickets；关闭后的读取选了 ticket_read_v1，
而非能够核对 closed 状态的 ticket_closed_read_v1。
DSL 和操作策略检查通过，TaskContract 意图门禁以
INTENT_TASK_CONTRACT_PLAN_MISMATCH 拒绝，**零业务请求**；不是被测服务 Bug。
保留本次失败及第三轮的独立结果，未将它删除、重试成功后改记 PASS 或放宽预期。

静态核对确认：当前公开目录中这两种读取策略，除 ID 外其余元数据完全相同。
其受信任断言实际不同，模型却缺少明确的测试用途说明；工单账号也使用预置 Bearer，
无需登录操作。上述是已确认的信息表达缺口，与失败可能有关；本轮没有消融实验，
不能唯一归因，也没有在 G501 上修改提示后调分。
