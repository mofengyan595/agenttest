## 真实执行证据与固定提案分别归因

第三实验室 fixture 的 evidence_gap 故障首次查验返回错误状态，后续同资源只读查询正常。
原业务仍 ASSERTION_FAILED，但不能由一次失败推断持续性缺陷。readback 故障则在相同角色、资源、
策略和 HTTP 检查均有效的第二次读取中重复失败，原规则才能支持持续读回不一致。

7 个专用 ASGI 开发案例与原证据回归合计 **21 passed / 25.55s**。7 项中固定提案明确 finish 弃权 3，
引擎拦截 3（不足证据的确定性提案、非法 JSON、外部报告引用），规则支持 2，模型提案与规则支持一致 1。
每项原业务结果和失败断言都保留；最多一次实际只读调查，没有恢复写入。
这些数字用于验证归因机制，提案均为固定 fixture，**不作为真实模型主动弃权或模型诊断质量成绩**。

跨报告引用不在当前执行证据目录内，不能获得采信；未产生实际调查时，也不能仅凭“证据不足”回退文案
算一次模型正确弃权。已有回归继续检查角色、资源生产者、父失败、GET、实际请求与相同策略模板等条件。
阶段5真实模型按实际保存的决策/提案分别计数，不仅查看最终 finding。
