# 受控目标组合与离线评分

本阶段把原来分别固定的课程与 batch 路径组合起来，沿用同一个 Workflow、Policy Registry、Executor 和 Verifier。默认入口不变；显式使用 `mini_composed` Planner profile 才启用新的草稿类型。没有新增 Agent 架构、真实 Java 接入或模型调用。

## 支持哪些需求

需求由“角色创建带引号的课程名”加分号分隔的完整目标子句构成。例如：

```text
alice 创建课程“组合示例”；核对创建者读取一致；验证 bob 读取被拒绝；验证批准两行 CSV 批处理成功及两条结果。
```

| 目标子句 | 确定性预期 |
| --- | --- |
| `核对创建者读取一致` | 创建者读回同一个课程，编号和名称与创建依据一致 |
| `验证 bob 读取被拒绝` | alice 创建、成功读回后，bob 对同一课程的读取返回批准的 403；角色可互换 |
| `验证批准两行 CSV 批处理成功及两条结果` | 同一课程上传固定两行 fixture，有界等待 SUCCEEDED，再读取两条结果 |

支持一致性、一致性＋权限、批处理、一致性＋批处理、三者组合。目标子句可换序，但计划仍须满足依赖和必要先后关系。至少请求一致性或批处理；权限要求同时核对创建者读取。批处理沿用 alice 的批准范围，bob 批处理不获授权。

这是受控中文语法，不能宣称通用自然语言理解。重复目标、删除等额外目标、改变 CSV／条数、未知措辞或不完整关系均待审；系统不补写用户目标或更改断言。

## 规划与执行的分工

所有任务看到相同的六个操作、七项策略、两个角色和认证／绑定规则，只有 `user_task` 改变。不会根据任务把目录预先裁成答案，也不把开发标签或期望计划送给模型。Prompt 说明安全规则和依赖原则，不给出某条任务的完整步骤序列。

模型选择目标所需的操作、角色、策略、步骤及参数引用。草稿只允许引用固定 CSV fixture 和 poll 策略 ID；文件内容、文件路径、轮询次数、重试、凭据、URL、Header、断言均不由模型填写。可信转换器注入批准 CSV，原 Policy／Intent／Executor 仍会再次校验。

组合 Registry 仅为已有 mini 策略加命名空间，并将 batch 的课程来源绑定到共享创建策略。原断言、角色、CSV、轮询限制保留；普通步骤新增明确的 `poll=false` 和 `read_retries=0` 约束。它不为 CourseInsight 或外部目标授予权限。

计划校验按目标集合和偏序进行：每个角色先登录；资源消费者引用前序创建响应；创建者成功读取先于跨用户拒绝读取；batch 轮询先于结果读取。无依赖的步骤可以交错，全部目标复用一次课程创建；漏目标、额外操作或字面量资源 ID 都不能通过。

## 复现与审计

使用项目已有 `.venv` 和锁定的 `agent` 可选依赖；不需要 Key、Docker 或外网。Linux 将解释器替换为 `.venv/bin/python`。

```powershell
.\.venv\Scripts\python.exe scripts/check_composed.py --output runs/composed-demo
.\.venv\Scripts\python.exe scripts/check_composed.py --verify runs/composed-demo
.\.venv\Scripts\python.exe -m pytest -q tests/test_composed_plan.py tests/test_composed_workflow.py
```

输出目录必须是新的目录。第一条命令用**固定计划夹具**跑真实的进程内 HTTP／工作流校验，第二条只读归档重新评分，不再发起 HTTP。固定计划由独立保存的开发标签展开，不使用运行时意图解析器；它是引擎机制基线，不是自动规划器。

新开发集为 [P001–P012](../examples/composed-development.json)：七条支持需求、五条预期安全门禁拒绝，全部 AI 草案、DEVELOPMENT_ONLY / UNREVIEWED。七条覆盖五类目标组合、角色互换和子句换序；五条拒绝不计为模型主动弃权。当前没有独立人工审核或 holdout。

归档包含源码／策略／fixture 摘要、父提交与工作区状态、运行环境、原始脱敏 Workflow 报告、执行前捕获的计划证据、逐项结果及文件封印。重新评分使用归档中的标签和策略快照，检查任务、运行、契约、计划及结果身份，再核对汇总；不依赖当前目标或重新执行。摘要能发现文件替换，不能防御有系统写权限的人重写整个归档。

## 评分表达的新增范围

单独的开发协议检查 Operation／Role／Policy、参数值摘要、来源步骤、Selector、目标集合和必要顺序，并明确核对：

- CSV 完整 upload 对象摘要，包括字段、文件名和内容。
- PollPolicy 完整摘要，包括终态、进度约束、次数和间隔。
- 批准断言**模板**与绑定规则摘要、是否上传／轮询、零读取重试。
- 报告与计划绑定、所有预期步骤和真实 attempt、全部断言通过、Workflow 完整结束及需求满足。

模板摘要不冒充运行时动态断言摘要；响应生成的资源 ID 仍由原 Executor／Verifier 核验。仅报告 PASS、缺少步骤／attempt／断言、图未结束、需求不满足或任务哈希不一致，都不能算成功。故障注入保留 ASSERTION_FAILED，CSV／轮询证据变化会导致重新评分失败。

`covered_goals` 只有在目标的全部关联步骤及传递前置关系都符合标签时才列出该目标。部分步骤正确不等于整个目标已覆盖；例如缺少结果读取，batch 目标不会因上传或轮询存在而被列为已覆盖。

旧正式 Eval v2 仍拒绝未标注的 upload／poll，C/T/B 数据和历史成绩未改。新汇总明确输出 `formal_eval_v2_score=null`、`human_reviewed=0`、`real_model_calls=0`，不能与历史真实模型成功率合并。本轮仅验证新的表达与执行机制；真实模型能否按不同目标选择计划尚未测量。

下一准确里程碑：由独立审阅者确认新任务及标签，冻结未使用的留出集、模型配置和预算，再单独授权真实模型规划试验。此前先用上述离线入口展示目标组合、拒绝和证据审计，不继续围绕已用题调参。
