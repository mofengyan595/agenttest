## 实施

- 模型通道共享 `SuiteLedger` 调用与 Token 预留、结算。预留票据只结算一次。Focus、设计和附属分析以编码后输入上界加输出配额预留，ChatModel 在派发前执行同一账本检查。未派发不记调用。网关拒绝计调用，保留 `REFUSED`，取消或传输结局未知继续阻断。Deep Agents 使用现有 LangChain 工具调用中间件、重试和上下文压缩。原生调用计数中间件保留 Agent 上界，产品账本覆盖所有渠道。
- `ProjectBudget.suite_max_*` 作为该次项目任务或 Suite 的总额度，任务 `execution` 配置基数和增长上限。`agent_max_model_calls` 约束 Agent 调用，其余模型通道仍计入任务总额度。既有 `ModelSettings` 窗口是单次请求校验。时间受外层任务时限约束。操作员批准的 `TargetConfig.max_requests` 仍约束 HTTP，任务可以收紧且两种模式都禁止增长该额度。报告输出调用、Token、HTTP 的 limit、ceiling、used 和 remaining，以及预算拒绝维度和剩余义务。
- 历史 `final-prev/A/prerelease-adaptive-r1` 在 `supervision_24_group_1` 和 `supervision_25_group_1` 被项目预算拒绝，报告收尾显示 69 次调用、560,680 已知 Token，额度为 96 次、1,000,000 Token。固定使用窗口预留 480,000 + 8,192 会使剩余 439,320 不足，两次设计均未派发。新账本保留硬上界，按实际信封上界预留，避免大窗口本身阻断可支付的小请求。
- 增长依据为首次测得的义务断言、减少的阻塞及可信清理凭据。新方案和普通工具返回仅作诊断，重复读取和失败动作可以触发无进展停机。一次已确认异常可完成相应观测义务，异常仍在报告中。
- Focus 为明确的「删除后查不到」原文从同一子句中唯一 DELETE 与唯一读取动作映射生成顺序边，依赖和绑定仍由已有策略检查。只在模型误把负向批准样例填入 `exact_value` 的情形重新提取一次。授权冲突、用户字面量、角色和身份仍按原规则验证。
- 上线前正向组复用现有依赖闭包，负向按操作、策略依赖、角色构建大小不超过四的候选批。Agent 从现有工具选择批次，执行使用受约束的负向槽位及同一预检。全局覆盖使用策略 ID，多次观测不扩大覆盖分子。报告记录批次状态、未测策略、最低 HTTP 数和实际用例、清理证据。相同资源跨负向变体的前置复用仍有限。
- 只读复核写入产品的同一持久证据流。完成判据仍独立计算。清理判定使用实际执行、同资源绑定和 404/410 断言，拒绝把规划前置条件或 204 单独当作证明。已创建资源的成功更新不再计成另一份创建。跨用例仅在同一目标指纹、同一删除/回读身份与角色、正确先后且无介入写入时复用批准的缺失读。
- 现有包裹靶场是服务端生成 ID 的集合 POST，没有已批准的按客户端关联键读取或列表回读策略。已执行的 422 保留 `CREATION_UNPROVEN`。可补批的验证策略需要可在前后精确匹配的唯一关联键、允许该操作的只读批准和确定性缺失判据。当前验收沿用历史靶场和批准目录，未添加验证权限。

## 冻结真实验收

### 首次成功、拒绝与分批收敛

- B 有效任务首次严格完成由 1/5 降为 0/5。不合理零请求由 5/15 降至 4/15，剩余为边界 r1、删除 r3 和调查 r1/r2。旧模糊样本三次均安全停止，最终批三次均由校验拒绝结束，缺少明确澄清。C 有效任务的首次严格完成为 0/5，15/15 获得业务执行，三个模糊样本均发出澄清且零业务 HTTP。
- A 功能 ADAPTIVE 3/3、FIXED 2/3。删除两臂均为 1/3。调查 FIXED 1/3、ADAPTIVE 0/3。A 的上线前 FIXED 覆盖 19、16、17/31，ADAPTIVE 覆盖 9、11、3/31。B 上线前最好 24/31，C 为 13、14、13/31。所有上线前任务均未严格完成。
- A 和 C 共九轮识别为上线前，均产生 7 个负向候选批。B 三轮被目标分类归为其他类型，沿用单义务补测。分类对「下周上线」「上线前」的处理仍需独立回归。批次存在依赖相同却多次创建前置资源的现象。
- A ADAPTIVE 减少约 33% 已知 Token，覆盖和完成没有稳定优势，尤其上线前覆盖低于 FIXED；本轮证据不足以推荐将自适应作为生产默认。B 模型调用从校正后的 144 增至 235，严格完成从 3/18 降至 1/18，新增请求带来了覆盖，但没有相应的完成收益。

### 异常与资源

60 轮有 60 个可用性故障机会及 6 个假 204 机会。实际观测到 22 个可用性故障与 5 个假 204，27/27 均按批准断言检出。另有 38 个可用性和 1 个假 204 未获得观测，没有据此判定服务正常。记录中 27 条可用性步骤断言失败及 6 条假删除步骤断言失败，多条可来自同一轮。未发现把正常响应标为异常或以空状态码判缺陷的记录。证据只确认批准断言所见的异常表现，保留对服务内部原因的不确定性。

账本记录 `CREATED_AND_CLEANED` 26、`CREATION_UNPROVEN` 126、`CLEANUP_UNPROVEN` 70、`CREATED_CLEANUP_FAILED` 6。实验结束有五轮假 204 靶场仍存 7 条记录，全部如实留在结果中。其余 55 轮靶场终态存量为零，存量仅用于验收复核。逐条核对 509 个靶场事件均匹配 READY 目录中的方法和路由，报告未见未知结局的写入或写入重放。进入 Deep Agents 的 48 轮均通过原工具权限探针。
