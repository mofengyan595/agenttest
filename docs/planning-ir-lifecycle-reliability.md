基线 `4dfe304fc259c8fc90bd9cf83ffab3fdcbfde6f8`。从[上一轮审计](agenttest-product-semantics-audit.md)的原始证据起步。`.eduwork/product-semantics-20261115/acceptance/` 保留冻结的三个删除位置和三个发布位置，包含 `run.json`、模型输出、靶场事件和实际报告。

## 删除后回读

原始三个删除位置在 HTTP 前失败。显式回读是 `ai_3 EXISTS`，旧 IR 只在删除和读取位于同一子句时尝试复用已有读取。跨子句因此额外产生 `ai_4 VERIFY_ABSENT`。旧图含 `ai_3→ai_2 LIFECYCLE_CLEANUP` 和原文约束的反向关系。前两个位置还把派生读当作原文顺序锚点，形成 `ai_2→ai_4→ai_3→ai_2`。

修复后先根据原文实例地址、顺序边、批准的资源身份和读取策略判断阶段。默认索引 0 仅在同一子句的操作和身份唯一时可解析到别的明确索引。显式读取保留其自己的来源和实例 ID。三个历史 Focus 固定重放都得到 `ai_1 createParcel → ai_2 deleteParcel → ai_3 readParcel/VERIFY_ABSENT`。`ai_1→ai_3` 保留数据依赖，`ai_2→ai_3` 保留原文顺序和缺失阶段约束。确定性重放没有发出 HTTP。

读取前置判定必须有相同创建策略、路径参数、选择器和获批的读取身份。明确要求 200 的读取不能被改写成 404。无获批缺失策略时显式回读要求保留待复核。归档的创建、存在读取、删除、缺失读取仍各有一个实例。多个无法区分的同类创建仍拒绝。Compiler 按子句、操作、身份、唯一未使用实例绑定，保留真正冲突与循环失败。

固定用例 `test_explicit_read_in_next_clause_is_the_absence_instance` 在修改前实际复现 `DEPENDENCY_CYCLE`。同场景另验证无批准缺失策略须拒绝。归档 M2 测试把临时代码中重命名的操作同时映射到顺序边，继续保留原四请求链路与断言。

## 完整发布与分批

旧发布范围先做摘要词元匹配，把「服务」锚定到 availability，三轮分母为 24、25、25。完整发布意图明确且没有指定单个对象时，使用项目批准目录的固定范围。窄接口请求仍依据原文。冻结历史证据重放为 18/31、13/31、13/31，严格完成仍均为 false。选中范围随 Focus 变化，缺失义务在完成判据和预算报告中保留。

批次只接受本批剩余获批负向变体及各自经验证的准备和清理步骤，禁止夹带普通用例。已有证据的批次和完整发布正向分组会在再派发前停止，聚合按批准策略 ID 计一次。清理拥有独立的身份引用。批次存在已批准且唯一匹配的缺失读时，预检把它接到同一资源删除之后，随后重新经过 Validator。非法 PUT/PATCH 后是否保留了全部初始字段尚缺证据，相关独立负向变体仍分别准备可追踪资源。

## 负向 POST 副作用观测

原包裹靶场为服务端生成 ID 的集合 POST。仅凭 422 或事后总存量无法回查该次请求。新增的约定只通过 `--observe-negative-posts` 在隔离靶场启用。`X-Lab-Correlation` 是合同声明、策略允许的公开关联键。靶场创建记录时保存键，获批 GET 以键查询全部匹配记录数。观测策略要求 HTTP 200 和 `$.count == 0`，从业务发布分母独立列为执行凭据，批准业务义务仍是 31。

预检先验证原提案，再用一次性关联键装配 GET→负向 POST→GET，并重新验证完整计划。两个新增 HTTP 计入原账本。只读结果必须分别通过固定的零计数断言，且实际查询值、发送的键、策略和身份一致才能写入 `CORRELATED_ABSENCE_BEFORE_AND_AFTER`。失败、缺证或键不匹配时保留 `CREATION_UNPROVEN`。未知写的禁止重放规则先于观测判定。对报告中已脱敏的值，保留确定性已通过断言和批准策略标识，关联凭据引用前后步及键的摘要。
