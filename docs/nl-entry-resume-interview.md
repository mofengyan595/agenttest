# 自然语言入口：简历与面试材料

适合补充Agent应用工程能力，不改变Java后端求职主线。技术栈为Python、FastAPI、LangGraph、
Pydantic、HTTPX、SQLite、MCP、React/TypeScript、pytest与GitHub Actions。

## 可用条目

- 实现项目级自然语言API测试入口，复用OpenAPI、批准策略与资源关系，从原始需求独立派生意图约束；
  模型生成受限DSL，单接口边界、跨接口流程与项目分组共用执行器，新增支持需求无需手写完整步骤。
- 实现SQLite任务元数据、幂等提交、串行调度、SSE进度、取消与配置版本检查；补充需求创建不可变新
  计划并共享剩余额度，重启将未完成任务标记中断，不重放写入；工作台提供会话/CSRF/同源保护。
- 将业务断言、模型只读调查建议和规则症状分层保存，冻结两业务域12条新需求、每题三轮验证；保留
  待审、预算未覆盖和失败，完整通过的计划以固定模板导出pytest，后续回归不调用模型。

不要写任意自然语言全覆盖、零人工配置、生产级多租户、长期记忆、自动恢复、通用准确率或节省工时。

## 面试案例：不手写步骤，怎样防止模型漏测后自认成功

问题：以前每个新需求都要提供完整TaskContract。直接删除它，会让模型的计划同时充当验收标准。

失败场景：用户要求创建、关闭、回读，模型漏了关闭步骤，或者选择了开态读取断言；只看合法JSON和
已执行请求都成功，就可能把缺失目标算成完成。

方案：操作员一次配置动作词、策略引用、角色和状态关系。系统先从原文及批准绑定派生认证前置条件、
动态ID来源和目标顺序；独立约束只用于本地校验，不送模型，也不从生成计划反推。未知语义保留待审。

替代方案取舍：提示不能代替门禁；生成后静默补步骤或重排会掩盖模型遗漏。逐题预写映射又会保留原有
人工编排负担，因此只支持能从项目级关系确定核验的目标。

实现：`goal_derivation`与`project_goals`在规划前产生独立约束；`goal_suite`协调三层场景；原Workflow、
DSL、Intent、Executor和Verifier负责校验与执行。任意额外操作、错角色、错来源或错顺序在HTTP前拒绝。

验证与边界：离线测试覆盖遗漏/额外操作/角色/来源/顺序、配置漂移、预算、未知用量和跨run隔离；
真实结果按目标、计划、执行、断言与完整任务分别统计。多义getCourse需要明确业务预期，删除工单
没有批准能力；工单项目11次需求受10次授权限制，部分通过不表示项目测试完整。

## 面试案例：执行服务怎样避免误重放

问题：浏览器超时或服务重启，可能让同一写测试重复执行。

失败场景：用户重复点击、请求已发送但页面没收到响应，或第二个进程启动时把第一个活跃任务误标中断。

方案：提交ID幂等、服务端原子状态/版本迁移、单服务OS锁和串行队列。取消保留已发送计数，重启不重建
原始请求；新补充创建新任务和新资源，但共享原剩余预算。每次模型调用、反馈和实际派发前检查配置身份。

替代方案取舍：没有可验证幂等业务协议时，自动重试写入可能产生重复数据。当前明确不提供请求恢复、
自动回滚或自动修复，也不通过清空状态来制造成功。

验证与边界：实际SQLite/ASGI、API会话安全和浏览器关键交互均有验证；目前是本地受控任务服务，
不是生产多租户平台。无模型pytest负责稳定回归，不能当作第二次模型规划成功。

量化时必须同时注明：原真实三轮完整计划23/36、完整任务15/36、指定故障8/9；首次新需求1次真实模型通过并导出无模型回归。追加尝试不替换首次成绩。[完整统计与归因](nl-entry-value-report.md)。
